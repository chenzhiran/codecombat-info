1　算法与程序

Algorithm vs Program

1.1 算法 ≠ 程序

这两个词经常被混着用，但它们不是一回事。

算法（Algorithm）程序（Program）
是什么解决问题的步骤和方法用某种语言把算法写出来
和语言有关吗无关——同一个算法可以用任何语言实现有关——C++ 程序不能用 Python 编译器跑
能被机器执行吗不能，它是"想法"能，编译之后就是可执行的
例子"从右往左逐位比较，取较大者"具体的 C++ 代码
打个比方： 算法和程序的关系，就像菜谱和厨师的关系——
菜谱写的是"这道菜怎么做"，谁来照着做都做得出同一道菜；
而程序是"某一位厨师用他会的语言，把这张菜谱说出来"。
同一张菜谱可以让很多厨师说成不同的话；同一个算法也可以写成很多种语言的程序。

1.2 算法的五个特征

算法必须具备的五个特征： ① 有穷性——步骤必须是有限的，做完一定会停。死循环不是算法。
② 确定性——每一步的含义必须明确，不能有歧义。"加一点盐"不行，"加 3 克盐"才行。
③ 可行性——每一步都必须是能真正做到的。"把水烧到 500 度"不算。
④ 输入——有 0 个或多个输入。
⑤ 输出——至少要有一个输出，否则算了半天什么都没得到。
判断：这几段描述算不算算法？ TEXT 
① "不断地把 n 加 1，直到天荒地老"        → 不是。没有"有穷性"

② "把一堆数排一下序，看着顺眼就行"        → 不是。没有"确定性"

③ "求 n 的阶乘：result = 1；
     对 i 从 1 到 n：result = result × i；
     输出 result"                        → 是。五条全满足

④ "随便想一个数"                          → 不是。没有输出，也没有确定性
要点　判断的关键往往在"会不会停"和"有没有明确输出"这两条上

2　三种描述方式

Three Ways to Describe

2.1 自然语言、流程图与伪代码

同一个算法，可以用三种方式说给别人听：

方式长什么样优点缺点
自然语言用中文一步步写出来谁都能看懂容易啰嗦、容易有歧义
流程图方框 + 菱形 + 箭头分支和循环一目了然步骤多了会画得很长
伪代码像代码又不是代码的简写最接近最终程序需要一点编程基础才看得懂
同一件事，三种说法 TEXT 
【自然语言】
  先做一个变量 max 记下第一个数；
  然后从第二个数开始一个个看过去，遇到更大的就更新 max；
  看完所有数，输出 max。

【伪代码】
  max ← a[0]
  for i 从 1 到 n-1：
      if a[i] > max：max ← a[i]
  输出 max

【C++ 程序】
  int max = a[0];
  for (int i = 1; i < n; i++)
      if (a[i] > max) max = a[i];
  cout << max;
对比着看　伪代码已经很接近代码，但省掉了类型、分号这些细节——先写伪代码再写代码，思路会清楚很多

2.2 流程图的四种基本图形

记住这四个形状： 圆角框——开始 / 结束；
矩形框——处理，也就是"做一件事"；
菱形框——判断，有两条出口；
平行四边形——输入 / 输出。
考试时看到一张流程图，先找菱形框有几个——数出了几个菱形，就知道这段逻辑里有几个判断。

3　例子：找出最大值

Worked Example

3.1 先把问题说清楚

这是个三级考试里出现频率极高的经典例子，我们完整走一遍。

问题： 给出一排数，找出其中最大的那个。

先说清楚步骤——这里最关键的是：一开始的 max 该设成什么？

找最大值的算法（伪代码） TEXT 
1. 读入 n 个数，存进数组 a
2. max ← a[0]              ← 先"假设"第一个数是最大的
3. i ← 1
4. 当 i < n 时：
      如果 a[i] > max，就 max ← a[i]
      i ← i + 1
5. 输出 max
问题　第 2 步为什么是 max ← a[0]，而不是 max ← 0？

3.2 完整走一遍

为什么 max 一开始要取第一个数？ 因为数组里的数可能全是负数。
如果写 max = 0，那遇到 {−5, −3, −9} 这样的数据， 程序会输出 0——可 0 根本不在这些数里面。
而取 a[0] 就绝对安全：它是数组里真实存在的数， 后面遇到更大的自然会替换。
用 {5, 9, 3, 7, 2} 走一遍 TEXT 
初始：max = a[0] = 5

i=1：a[1]=9，9 > 5 成立 → max = 9
i=2：a[2]=3，3 > 9 不成立 → max 不变
i=3：a[3]=7，7 > 9 不成立 → max 不变
i=4：a[4]=2，2 > 9 不成立 → max 不变

循环结束，输出 max = 9     ✔
观察　max 里始终装着"到目前为止见过的最大的数"——这就是这个算法的灵魂

4　好算法的标准

What Makes a Good Algorithm

4.1 正确性优先

同一个问题往往有很多种解法。那怎么判断哪个更好？三级主要看两点：正确和效率。

标准含义不满足会怎样
正确性对所有合法输入都能给出正确答案算错了，其他一切免谈
效率花的时间少、占的空间小数据一大就跑不完
为什么"正确性"必须排第一？ 一个算法再快，只要答案不对，就等于没做。
而"正确"不只是"样例过得了"——还要考虑边界情况：
空数组怎么办？全是负数怎么办？只有一个数怎么办？
把这些都试过还正确，才算真的正确。

4.2 然后是效率

打个比方： 两个算法都能算对，比的就是谁更省事——
一个要跑一千步，一个只要跑十步，结果一样，但花的时间和力气差了一百倍。
所以在保证"答案对"的前提下，步数越少、越省空间，就是越好的算法。
同一个问题，两种算法差多少？ TEXT 
问题：求 1 + 2 + 3 + … + n

【算法一：一个一个加】
  sum ← 0
  对 i 从 1 到 n：sum ← sum + i
  要加 n 次 —— n = 1000000 时就要加一百万次

【算法二：用公式】
  sum ← n × (n + 1) / 2
  不管 n 多大，只算一次

n = 1000000 时：
  算法一：一百万次加法
  算法二：两次乘法、一次除法

结果完全一样，效率差了五十万倍。
结论　好的算法能用更少的步骤解决同一个问题——这就是"效率"的意义

5　三种基本结构

Three Basic Structures

5.1 顺序、分支、循环

一句话记住三种结构： 顺序——一条道走到底，一步接一步。
分支——遇到岔口做选择，两条路只走一条（if / else）。
循环——条件成立就重复做，不成立才往下走（for / while）。
再复杂的程序，拆开来也还是这三种结构的组合。

5.2 一段程序的完整骨架

把三种结构放在一段代码里 C++ 
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;                            // 输入

    int sum = 0;                          // 处理前的准备
    for (int i = 1; i <= n; i++) {        // ← 循环结构
        if (i % 2 == 0) {                 // ← 分支结构
            sum += i;                     // ← 顺序结构
        }
    }

    cout << sum << endl;                 // 输出
    return 0;
}
拆解　cin → 准备 → 循环（里面套着分支，分支里是顺序）→ cout
这就是"顺序 + 分支 + 循环"的典型组合
写程序之前的三个问题： ① 数据从哪来？（输入是什么）
② 要重复做什么、重复多少次？（哪一部分该用循环）
③ 中间要不要做判断？（哪里需要分支）
把这三个问题答清楚，再动手写代码——这就是"先画图纸，再挖矿道"。

#include <iostream>
using namespace std;

int main() {
    // 【步骤一】顺序：先把要用的东西准备好
    int total = 0;

    // 【步骤二】循环：要走的位置一共 6 个
    for (int i = 0; i < 6; i++) {
        hero.moveRight();

        // 【步骤三】分支：有敌人就打，没有就继续
        int enemy = hero.findNearestEnemy();
        if (enemy) {
            hero.attack(enemy);
        }

        total++;                       // 顺便记下走了几步
    }

    cout << total << endl;
    return 0;
}

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
这一单元的题，考的都是"你有没有真的读进去"。四条最容易掉进去的。
1
把"没有输出的描述"当成了算法。
扣哒鸭：算法至少要有 0 个或多个输入，但一定要有输出。
一段流程算完之后什么都没得到，那它只是"动作"，不是算法。
检查：输入是什么？输出是什么？答不上输出，就不是算法
2
写循环条件时用了赋值号 =。
扣哒鸭：这个坑太经典了，必须单独说。
for (int i = 0; i = 0; i++) 中间那句是赋值，不是比较——
它把 0 赋给 i，整个表达式的值就是 0（假），循环一次都不执行。
正确写法：判断相等要用 ==；循环条件一般写 i < n
3
以为流程图的菱形框只有一个出口。
扣哒鸭：菱形就是"判断"，判断必然有两种结果——
所以它一定有"是 / 否"两条出口线。
看到菱形只有一条线的流程图，那张图肯定画错了。
正确认识：圆角框=开始结束、矩形=处理、菱形=判断（两条出口）、平行四边形=输入输出
4
只拿样例试过就认为算法"正确"。
扣哒鸭：样例只是很多可能输入里的一个。
找最大值的例子：拿 {5, 9, 3} 试没问题， 换成 {−5, −3, −9} 就露馅了（因为 max 初值设成了 0）。
正确 = 对所有合法输入都正确。
检查边界：空数据、全是负数、只有一个数、最大数在开头 / 结尾

改编自 2026 年 9 月 · C++ 三级 · 第 3 题单选题
下面程序的运行结果是（　　）。
#include <iostream>
using namespace std;
int main() {
    int x = 1;
    for (int i = 0; i = 0; i <= 5) {
        x++;
    }
    cout << x << endl;
    return 0;
}
A.1　　B.10　　C.15　　D.程序编译错误
查看答案与详解
答案：A。关键在 for 的第二段（条件）写的是 i = 0，这是赋值不是比较。
执行过程：
① 先做第一段 int i = 0，i 变成 0；
② 检查第二段 i = 0——这是"把 0 赋给 i"，整个表达式的值就是 0， 在条件里 0 代表假；
③ 条件为假，循环体一次都不执行；
④ 所以 x 始终是 1，输出 1。
为什么不是编译错误？因为 i = 0 本身是个合法的表达式（有值、有副作用）， 编译器最多给个警告，不会报错。
正确写法应该是 i <= 5（或者 i < 5）。
对应小节5.1 顺序、分支、循环。
改编自 2026 年 6 月 · C++ 三级 · 判断题 第 9 题判断题
枚举可以在保证不漏解的前提下缩小枚举范围，不是必须遍历全部可能。（　　）
查看答案与详解
答案：正确（√）。"枚举"的核心要求是不重不漏，而不是"把宇宙间所有数都试一遍"。
举例：求 1 到 1000 之间的水仙花数（三位数）， 枚举范围只取 100 ~ 999 就够了——因为三位数只可能落在这个区间里， 完全没必要从 0 试到 1000000。
再比如：知道"兔的只数不可能超过头的总数"，那循环到 tou 就可以停。
合理的缩小范围既不影响正确性，又能大幅提速——这正是"好算法"的体现。
对应小节4.2 然后是效率。
改编自 2026 年 6 月 · C++ 三级 · 判断题 第 10 题判断题
某流程图逻辑为：初始化 i = 0、sum = 0； 当 i <= n 成立时，执行 sum = sum + a[i]， 再执行 i = i + 1；循环结束后输出 sum。 该流程图可以正确计算一维数组 a[0] ~ a[n] 全部元素的总和。（　　）
查看答案与详解
答案：正确（√）。逐条核对：
① 初值：i = 0、sum = 0——下标从 0 开始，累加变量从 0 开始，都对。
② 条件：i <= n——数组有 a[0] 到 a[n] 共 n+1 个元素， 用 <= 正好能把最后一个 a[n] 也纳进来 ✔
③ 推进：每轮 i = i + 1，i 会依次取 0、1、…、n，一定会终止 ✔
④ 结果：sum 恰好累加了全部 n+1 个元素 ✔
常见的错法是把条件写成 i < n——那样会漏掉最后一个 a[n]。
做这类题的方法：拿 n = 2 的小数据，把每轮 i 和 sum 的值列出来，一看就清楚。
对应小节3.2 完整走一遍。

A.有穷性——步骤有限，做完一定会停
B.确定性——每一步含义明确，没有歧义

原创练习题判断题
评价一个算法时，只要它在样例数据上跑得出正确结果， 就可以认为这个算法是正确的。（　　）
查看答案与详解
答案：错误（×）。正确性要求"对所有合法输入都正确"，不是"样例过得了"。
经典反例：求最大值的算法里，如果把 max 的初值写成 0， 那么对 {5, 9, 3} 这类全是正数的数据完全正确；
可一旦输入全是负数 {−5, −3, −9}，它会输出 0——而 0 根本不在数据里。
所以验收算法时一定要试边界数据：空数据、全负数、只有一个元素、最大元素在开头或结尾。
对应小节4.1 正确性优先。
原创练习题编程题
题目要求：读入 n 和 n 个整数，输出最大值和最大值第一次出现的下标。
样例：输入 5 和 5 9 3 7 2，输出 9 1。
查看参考答案与要点 
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    int a[1005];
    for (int i = 0; i < n; i++) cin >> a[i];

    int mx = a[0];          // ★ 初值取第一个数，别取 0
    int pos = 0;            // 记录最大值所在下标

    for (int i = 1; i < n; i++) {
        if (a[i] > mx) {    // 注意是 > 而不是 >=
            mx = a[i];
            pos = i;
        }
    }

    cout << mx << " " << pos << endl;
    return 0;
}

要点：
① mx 的初值必须取 a[0]—— 取 0 的话，遇到全负数的数据就错了；
② 用 > 而不是 >=， 是为了保证记录的是"第一次出现"的下标（遇到同样大的值不更新）；
③ pos 要跟着 mx 一起更新， 两者必须同步，否则下标和数值会对不上；
④ 循环从 i = 1 开始，因为第 0 个已经在初值里"比过"了。
对应小节3.1 先把问题说清楚；3.2 完整走一遍。
