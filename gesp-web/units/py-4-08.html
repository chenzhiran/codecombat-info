1　数据为什么会丢

Why Data Disappears

1.1 数据为什么会丢

1.2 一句话

打个比方： 程序里的变量就像写在沙滩上的字——只要程序一结束（涨潮），字就被冲掉了。
想让字留到明天，就得把它刻进石头——这就是把数据写进文件（硬盘）。
文件放在硬盘上，断电也不丢；变量放在内存里，程序一停就没了。
一句话： 变量活在内存里，程序一结束就没了；文件存在硬盘上，可以跨程序、跨时间去读。
这就是为什么"存档"必须用文件。

2　读文件

Reading Files

2.1 读文件

三步：打开 → 读取 → 关闭 Python 
# 最基础的写法
f = open("score.txt", "r", encoding="utf-8")   # r = read 读取
content = f.read()                              # 一次读出全部内容
print(content)
f.close()                                       # 一定要关！

# 更推荐的写法：with 会自动关闭
with open("score.txt", "r", encoding="utf-8") as f:
    content = f.read()
print(content)
要点　encoding="utf-8" 一定要写，否则中文可能变乱码
读取方式写法得到什么
全部读出f.read()一整个字符串
按行读出f.readlines()一个列表，每行一个元素
逐行遍历for line in f:一次一行，最省内存

2.2 处理文本行的小技巧

处理文本行的小技巧： 每行末尾都会带一个换行符 ， 处理前先用 line.strip() 去掉它。
忘了 strip，字符串比较很容易"看起来一样却不相等"。

Writing Files

3.1 写文件

写入与追加 Python

with open("out.txt", "w", encoding="utf-8") as f:
    f.write("第一行
")
    f.write("第二行

# a = append 追加（在末尾接着写）

"r"只读文件不存在会报错
"w"写入，会清空原内容⚠️ 小心！
"a"追加，写在末尾较安全

3.2 最容易出事故的一点

最容易酿成"事故"的一点： "w" 模式打开文件会立刻把原内容清空。
如果只是想加一行，千万要用 "a"。
考试里也爱考这个区别。

4　异常是什么

What Is an Exception

4.1 异常是什么

程序在运行时遇到"没法继续"的情况，就会抛出异常。 如果不处理，程序会直接停在那里。

异常名什么时候出现例子
ZeroDivisionError除以 010 / 0
ValueError类型对但值不对int("abc")
TypeError类型不匹配"5" + 5
IndexError下标越界[1,2][5]
KeyError字典里没有这个键{"a":1}["b"]
FileNotFoundError文件找不到open("没有这个.txt")

5　try-except

Catching Exceptions
try-except 的三种常见写法 Python 
# 写法一：基础版
try:
    n = int(input("请输入一个整数："))
    print(100 / n)
except:
    print("输入有误，或者除数为 0")

# 写法二：指定要抓哪个异常（推荐）
try:
    n = int(input())
except ValueError:
    print("这不是一个合法的整数")

# 写法三：多个 except + finally
try:
    f = open("data.txt")
    s = f.read()
except FileNotFoundError:
    print("文件不存在")
finally:
    print("不管成功失败，这句都会执行")
要点　except 异常名: 抓特定错误；finally 里的代码一定会执行
三个关键字的分工： try——放"可能出错的代码"；
except——出错了怎么办；
finally——不管出不出错都要做的事（比如关文件）。
不是所有代码都要套 try——只在"你确实预感到可能出错、并且知道怎么处理"时才用。

我们中间的间谍

故事：高台的城门口挂着一块告示牌，牌上写着一行字。 守门人只告诉你一个字：念出第 0 个字符。
你愣住了。戈登笑了：字符串也是"一格一格"的， 第 0 个字符就是最左边那一个。
他补了一句：不过要小心——字符串太短，硬去取就会出错。这就是为什么要有异常处理。

思路：字符串支持下标访问：s[0] 取第一个字符， len(s) 求长度。配合 try-except，即使取越界了程序也不会崩。

重点示例：字符串下标 + 越界保护 Python 
s = "Hello World"

hero.say(s[0])            # 会喊出 'H'（第 0 个字符）
hero.say(len(s))          # 会喊出 11（一共 11 个字符）

# 如果字符数不够，硬取就会 IndexError —— 这时就该兜一下
try:
    hero.say(s[20])
except IndexError:
    hero.say("这个位置没有字符")
要点　字符串和列表一样有下标；越界会抛 IndexError，用 except 接住即可
和本单元的关系： 读数据这件事随时可能出意外——文件不存在、字符不够长、输入不是数字。
不要指望程序永远顺利，而要事先想好"出了意外该怎么办"。 这就是异常处理的价值。

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
文件和异常这两件事，坑都在"细节"上。四条，条条都能让你白忙一场。
1
用 "w" 模式打开文件，把原内容清空了。
扣哒鸭：只有确实要"重写整份文件"时才用 "w"。
想保留原内容接着写，必须用 "a"。这是我见过最惨的一类事故。
正确写法：追加内容用 open("f.txt", "a")
2
忘了写 encoding，中文变成乱码。
扣哒鸭：Windows 上默认编码不一定是 UTF-8， 含中文的文件一定要显式写 encoding="utf-8"。
正确写法：open("f.txt", "r", encoding="utf-8")
3
把整个程序都包进 try 里。什么都抓，结果把 bug 也藏起来了。
扣哒鸭：except: 什么都不写，会连"键盘中断"都抓住， 程序像死了一样。
只 try 你真正预期会出错的那几行，并且指定异常类型。
正确做法：try 的范围尽量小，except 写明异常类型
4
读文件时不处理行末的换行符。比较字符串总是失败。
扣哒鸭：每行末尾都有 。 拿它去和 "apple" 比较永远不相等——因为实际是 "apple "。
记得 line.strip()。
正确做法：line.strip() 去掉首尾空白与换行

改编自 2026 年 9 月 · Python 四级 · 第 8 题单选题
把货单存进文件时，需要选一个"能同时读写、且文件指针从开头开始"的打开模式。
以下哪种文件打开模式符合要求（　　）。
A.'r'　　B.'w'　　C.'a'　　D.'r+'
查看答案与详解
答案：D。四种常见模式的区别：
'r'：只读，文件必须已存在，指针在开头；
'w'：只写，会清空原文件，指针在开头；
'a'：追加写，指针在末尾；
'r+'：可读可写，指针在开头，文件必须已存在 —— 正是题目要的。
顺带记住：'w+' 也是可读可写，但它会先把文件清空；想"在原内容上改"就选 'r+'。
打个比方：'w' 像"把黑板擦干净再写"，'a' 像"接着黑板末尾往下写"，'r+' 像"直接在黑板上又看又改"。
对应小节2 读文件 / 3 写文件。
改编自 2026 年 9 月 · Python 四级 · 第 10 题单选题
关于 try-except-else-finally 结构，以下说法正确的是（　　）。
A.如果 try 块中有 return 语句，finally 块将不会执行
B.finally 块通常用于释放资源，如关闭文件
C.一个 try 块只能对应一个 except 块
D.如果 try 块中发生了异常，那么 else 块也会执行
查看答案与详解
答案：B。finally 块的作用就是不管前面发生了什么，最后一定要做完的事——关闭文件、释放连接等收尾工作都放在这里。
A 错：即使 try 里有 return，finally 也一定会执行（而且是在 return 真正返回之前）；
C 错：一个 try 可以配多个 except，分别捕获不同类型的异常；
D 错：else 块只在没有发生异常时才执行，发生了异常就跳过它。
四段的含义：try 试着做 → except 出错了怎么办 → else 顺利做完了再做什么 → finally 无论如何都要做的事。
对应小节5 try-except。

原创练习题判断题
只要把代码放进 try 里，程序就一定不会崩溃。（　　）
查看答案与详解
答案：错误（×）。只有当抛出的异常类型和 except 声明的匹配时才会被抓住。
而且 try 只能处理"运行时错误"，语法错误（SyntaxError）在程序运行前就会被发现，根本轮不到 try。
另外：滥用 try 会掩盖 bug，不是好习惯。

原创练习题编程题
题目要求：编写程序，把 1 到 5 每个数的平方依次写入文件 squares.txt（每行一个）； 然后再把文件内容读出来打印，最后输出一共有几行。
查看参考答案与要点 
# ① 写入
with open("squares.txt", "w", encoding="utf-8") as f:
    for i in range(1, 6):
        f.write(str(i * i) + "
")

# ② 读取并打印
with open("squares.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()

for line in lines:
    print(line.strip())

print("共", len(lines), "行")

输出：1、4、9、16、25，共 5 行
要点：
① 写文件时 write() 只接受字符串， 数字要先 str() 转换；
② 每行末尾要自己加 " "，否则所有内容会挤在一行；
③ 读的时候用 readlines() 得到列表， 每行末尾带 ，打印前用 strip() 去掉；
④ 两处都用了 with，文件会自动关闭。

Unit Summary
戈登 · 齿轮工程师
四级到这里就收官了。最后三句话：
一、内存断电就没，文件才能留住数据；写用 "w"（清空）、加用 "a"（追加）。
二、开文件记得 encoding="utf-8"，推荐用 with 自动关闭。
三、异常不是洪水猛兽，try-except 就是那道安全阀。
从齿轮高台出去，前面就是星砂绿洲——那里有更多数学与算法等着你。

你在档案库前收获了什么

  • 内存 vs 文件——变量存在内存、程序结束即消失；文件存在硬盘、可以长期保留。
  • 读文件——open(路径, "r", encoding="utf-8")；用 read()、readlines() 或 for line in f 读取。
  • 写文件——"w" 会清空原内容，"a" 是追加；write() 只接受字符串。
  • with 语句——自动关闭文件，即使中途出错也能关，推荐优先使用。
  • 常见异常——ZeroDivisionError、ValueError、TypeError、IndexError、KeyError、FileNotFoundError。
  • try-except-finally——try 放可能出错的代码，except 处理错误，finally 无论如何都执行。
  • 使用原则——try 范围要小、要写明异常类型；别用它掩盖真正的 bug。
