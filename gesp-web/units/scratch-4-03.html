0　单元导语与目标

Before We Start

0.1 学习目标

  • 理解算法：解决一个问题的、清晰的、有限的步骤；

1　什么是算法

What Is an Algorithm

1.1 算法就是"解决问题的步骤"

图纸工坊的桌上摊着一张巨大的图纸。戈登指着它说： "图纸上画的不是零件，是"怎么造这个零件"的步骤。"

打个比方：算法就像菜谱。一份好菜谱要写清"放多少盐、炒几分钟"，而不是"差不多就行"。
照着菜谱谁都能做出这道菜——这正是"步骤明确"的含义。

1.2 同一个问题可以有多种算法

重要观念："能算出来"只是及格线，"算得省事"才是好算法。
后面的排序单元会看到：同样是排序，有的算法要比别人多比较好几倍。

2　算法好不好，怎么评

Evaluating Algorithms

2.1 第一条：对不对

2.2 第二条：步骤是多是少

一个直观的例子：要在一个有 100 个名字的清单里找一个人——
· 挨个看：最坏要看 100 次；
· 先按拼音排好序再"折半找"：最多只要 7 次左右（每看一次就排除一半）。
这就是"算法不一样，效率差很多"。

2.3 第三条：好不好懂、好不好改

打个比方：两个人都能把你送回家——一个走小巷抄近路但你不认识，一个走大路绕一点但你一看就懂。
程序也是给人看的：起好名字、拆成函数，别人（和三个月后的你）才改得动。

3　从图纸到程序

From Blueprint to Program

3.1 第一步：把问题读成"要做什么"

3.2 第二步：写步骤、画流程图

3.3 第三步：拼成积木

重点示例：一段"读题 → 积木"的对照 图形化积木
读法　输入（询问）→ 初始值（设为 0、设为回答）→ 循环累加（重复执行直到）→ 输出（说）
流程图的用处：先把图上的方框数清楚，再动手拼积木。图上有几个框，脚本里就大致有几组积木——这样拼的时候心里有数，不会越拼越乱。

故事： 乐园的仓库每天收到一长串订单，每张订单上写着"货号 + 数量"。 要么按顺序一件件处理，要么先按货号归好类再处理—— 两种做法都能完成，但工作量差很多。

思路：先把任务拆成三件小事：读订单、分类、按类输出。 每件小事做成一个函数，主脚本就只剩三行调用——清楚、也好改。

重点示例：主脚本只留三步 图形化积木
主脚本：三行看清整体
读法　定义里是细节，主脚本是骨架——光看主脚本三行，就知道这个程序在干什么
自己试一试：把"读订单"这三行换成几十块积木直接写进主脚本，程序照样能跑。但你现在还看得懂它吗？还能一眼找出错在哪吗？

6　常见陷阱

Common Traps
陷阱 1：一上来就拼积木。题目还没读清就动手，拼到一半发现方向错了。
正确做法：先圈出输入、输出、约束，用中文把步骤写一遍。
陷阱 2：只看"能不能算出来"，不看"花多少步"。考试里常问"哪种算法更好"，考的就是效率意识。
正确做法：比较时先看对不对，再比较步骤多少（尤其看数据变大时的增长）。
陷阱 3：一个函数塞进整个程序。那和不用函数没区别，只是换了个名字。
正确做法：一个函数只负责"一件独立的小事"，名字要能说出这件事。
陷阱 4：所有积木一起写完再运行。一旦出错，几十块积木里不知道是哪一块的问题。
正确做法：做好一个函数就单独调用测一次，确认对了再往下做。

7　题目练习

Practice

第 1 题改编自 2026 年 9 月 · 图形化编程 四级 第 2 题，其余为原创练习题。

改编自 2026 年 9 月 · 图形化编程 四 级 · 第 2 题单选题
某程序用循环做累加，它的流程图如下所示。执行这段程序后，输出的结果是（　　）。
A.6
B.7
C.8
D.9
查看答案与详解
答案：C。读流程图的通用方法就三步：
① 顺着箭头走，遇到矩形框就执行它写的事；
② 遇到菱形框就判断一次，按"是 / 否"选一条路；
③ 遇到绕回去的箭头，就说明这是循环——把每转一圈的结果记在手边，一圈一圈算。
这道题里循环在累加，把每一圈的和写下来，最后输出的就是 8。
要点：流程图题最稳的办法是在草稿纸上画一张"每转一圈时各变量是多少"的小表，不要光盯着图硬看。
对应小节3.2 从流程图读算法。
原创练习题单选题
关于"算法"的说法，下面哪一个不符合算法的要求（　　）。
A.步骤清晰，每一步都明确
B.有一定的输入，并产生结果
C.步骤要足够多，越多越好
D.步骤有限，执行下去一定会结束
查看答案与详解
答案：C。算法要求的是"步骤清晰、有限、能结束"，并不是越多越好——在同样正确的前提下，步骤越少越好。
A、B、D 都是算法的基本要求：明确、有输入输出、有限且会结束。
对应小节1.1、2.2 算法的要求与评价。
原创练习题单选题
要从一张有 1000 个名字的名单里找出某一个人。下面关于两种做法的说法，正确的是（　　）。
A.两种做法一样快
B.先排序再查找，通常比从头挨个找更省事
C.从头挨个找一定更快
D.只要程序能写出结果，就说明算法是好的
查看答案与详解
答案：B。同一个问题可以有多种算法，而"能算出来"只是及格线——
挨个找最坏要看 1000 次；先把名单排好序，之后每次查找都能"排除一半"，大大减少步骤。
D 错："能出结果"和"算法好"是两回事，评价算法还要看步骤多少、好不好懂。
对应小节1.2、2.2 多种算法与效率。
原创练习题单选题
面对一道复杂的综合编程题，下面哪种做法最合理（　　）。
A.想到哪儿写到哪儿，一口气把积木拼完
B.先读清题目（输入、输出、限制），把步骤写下来，再拆成几个小函数分块完成
C.先把所有积木拖到脚本区，再想怎么连
D.直接抄一个差不多的程序改改
查看答案与详解
答案：B。这正是四级考纲要求的流程：分析问题 → 写步骤 / 画流程图 → 拆成模块 → 分块实现与调试。
A、C 错：没有想清楚就动手，很容易拼到一半发现方向错了、又找不出错在哪一块；
D 错：题目要求往往不一样，硬抄会错得莫名其妙。
对应小节3.1～3.3、4.1～4.2 从图纸到程序。
原创练习题多选题
用函数把大问题拆成几个小问题，有哪些好处（　　）。
A.每个函数只做一件事，写起来更容易想清楚
B.主脚本只剩几行调用，整体结构一眼看得懂
C.出错时能缩小范围，只要单独测那一个函数
D.拆成函数之后，程序一定会跑得更快
查看答案与详解
答案：A、B、C。这三条正是模块化的三大好处。
D 错：拆成函数主要让程序"好写、好读、好改、好调"，它执行的工作量和原来一样——并不会让计算机算得更快。
对应小节4.1、4.2 模块化搭建。
原创练习题判断题
在评价一个算法时，只要它能算出正确的结果，就不需要再考虑它执行步骤的多少了。（　　）
查看答案与详解
答案：错误（×）。正确只是第一条要求。评价算法通常还要看两点：
① 步骤多少（效率）——同样能算对，花十步和花一千步差别很大；
② 好不好懂、好不好改——程序是给人看的。
对应小节2.1～2.3 算法好不好怎么评。

8　本单元小结

Unit Summary
戈登 · 机械师
这一单元学的是"怎么想"，不是"怎么拼"。
一套流程：读题（输入/输出/限制）→ 写步骤 → 画流程图 → 拆成函数 → 分块做分块调；
三个标准：对不对、步骤多少、好不好懂。

你在图纸工坊里学到了什么

  • 算法：解决问题的清晰步骤，有输入输出、每步明确、有限且会结束；
  • 同一问题多种算法：都能算对，差别在花了多少步；
  • 三条评价标准：正确性 → 步骤多少 → 好不好懂好改；
  • 四个环节：读题 → 写步骤 / 画流程图 → 拼积木 → 调试；
  • 模块化：拆成小函数，分块做、分块调，主脚本只留调用。
