1　从蓝图到产品

From Blueprint to Product

1.1 为什么要"类"

先看看"结构体"不够用的地方 Python 
# 先用字典表示一只机械鹰
eagle = {"name": "小灰", "speed": 80, "hp": 20}

# 字典只能"装数据"，不能"带动作"。
# 想让鹰飞一下、掉一点血，只能在外面写函数：
def fly(e):
    e["hp"] -= 5
    print(e["name"], " 飞了一圈，血量 ", e["hp"])

# 问题：数据和行为是分开的。
# · 谁都可以直接改 e["hp"] —— 想绕过 fly 就绕过去了
# · 函数一多，得记住"哪个函数管哪只鹰"，很累
两个痛点　 ① 数据和操作它的是分开的，用起来得两边都记着；
② 数据完全敞开，谁都能随手改，改坏了也查不出来
面向对象的核心想法： 把"数据"和"操作这些数据的函数"打包成一个整体， 这个整体就叫类（class）。
而且还可以给数据加上"门禁"—— 不让外面直接碰，只能通过类自己提供的函数来操作。
这样一来，数据从哪来、被谁改的，全都管得住了。

1.2 类与对象的关系

一句话分清"类"和"对象"： 类 = 蓝图（设计图）；对象 = 按这张图造出来的实物。
类只描述"应该长什么样、能做什么"—— 它本身不占内存、也不是任何一只具体的鹰。
对象才是真正存在的那一只—— 它有自己具体的属性值（这只鹰叫"小灰"、速度 80）。
一张蓝图可以造出无数个对象—— 它们的"结构"相同，但"内容"各不相同。
对照着看 Python 
class Eagle:          # ★ 这是"类"——蓝图
    ...

a = Eagle()           # ★ 这是"对象"——照蓝图造的一只
b = Eagle()           # ★ 这是另一个对象——同一张图造的又一只

a.name = "小灰"
b.name = "小白"
# 它们结构一样，但内容各管各的 —— a 改名不会影响 b
最容易记的一句话　 类是一种"类型"，对象是这个类型的"变量"
就像 int 是类型、int x; 里的 x 是变量——
Eagle 是类型、Eagle a; 里的 a 是变量

2　定义一个类

Defining a Class

2.1 class 的基本写法

把一个"计数器"做成类 Python 
class Counter:
    def __init__(self):        # ★ 构造函数：创建对象时自动执行
        self.value = 0         # 成员变量（数据）

    def add(self):             # ★ self 就是"我自己"
        self.value += 1

    def reset(self):
        self.value = 0

c = Counter()          # 创建对象
c.value = 10           # 用点号访问成员
c.add()                # 调用成员函数
print(c.value)         # 11
OUTPUT　11
三处格式要求　 ① class 开头；② 成员写在花括号里； ③ 右大括号后必须有分号——和结构体一样
类和结构体，其实非常像。 在 Python 里，struct 和 class 几乎是一回事—— 它们都能装数据、都能带函数、都能继承。
唯一的区别是"默认的访问权限"：
struct 里默认是 public（外面能直接访问）；
class 里默认是 private（外面不能直接访问）。
所以写类的时候，public: 那一行基本是必须写的。

2.2 访问控制：public 与 private

关键字含义谁能访问
public:公开的类里面的成员、外面的使用者，都能访问
private:私有的只有类自己的成员函数能访问
protected:受保护的类自己 + 它的派生类能访问
私有成员外面碰不到 Python 
class Base:
    def __init__(self):
        self._value = 10           # ★ 下划线开头 = "这是内部的，别碰"

class Child(Base):
    def get(self):
        return self._value         # 语法上能读到，但子类不该依赖它

# 正确做法：让基类提供一个公开的读接口
class Base2:
    def __init__(self):
        self._value = 10

    def getValue(self):
        return self._value         # ★ 只暴露"读"，不暴露"改"
关键区别　 private 连派生类都不给看；protected 给派生类看
所以"派生类能不能直接访问基类成员"要看清是私有还是受保护

3　构造函数与析构函数

Constructors & Destructors

3.1 创建时就初始化好

构造函数：名字和类名一样，没有返回值 Python 
class Student:
    def __init__(self):            # ★ 构造函数：创建对象时自动执行
        self.age = 18
        print("新建了一个学生")

    def __del__(self):             # ★ 析构函数：对象被回收时执行
        print("这个学生被销毁了")

s = Student()          # ← 这里自动调用构造函数
print(s.age)           # 18
# 对象不再被任何变量引用时，__del__ 会被自动调用
OUTPUT
新建了一个学生
18
这个学生被销毁了
两个函数都不用你手动调用——一个在创建时、一个在销毁时自动执行
两个函数的四个特点： ① 名字——构造函数和类名完全一样； 析构函数是类名前面加一个 ~；
② 没有返回类型——连 void 都不写；
③ 自动调用——构造函数在创建对象时， 析构函数在对象销毁时（比如函数结束、delete 时）；
④ 可以重载——构造函数可以有多个版本（参数不同）； 析构函数只能有一个。
一条很容易被考到的规则：一旦自己写了构造函数，编译器就不再生成默认的。 如果你只写了 Student(int x) 这一个带参数的构造函数， 那么 Student s; 这种"不带参数"的写法就会编译报错—— 因为编译器看到你定义了构造函数，就不会再自动生成那个无参的默认版本了。
解法：要么再补一个无参的构造函数，要么创建对象时就把参数写上。
所以"编译器会自动生成无参构造函数"这句话， 只有在"你一个构造函数都没写"的时候才成立。

3.2 带参数的构造函数与初始化列表

创建对象时就给好参数 Python 
class Student:
    def __init__(self, name, age):     # ★ 带参数的构造函数
        self.name = name
        self.age = age

s = Student("小明", 12)                # ★ 创建时就把参数传进去
print(s.name, " ", s.age)              # 小明  12

# 参数多了容易传错顺序，可以写清楚名字
s2 = Student(name="小红", age=11)
两种写法效果一样　 在函数体里赋值，或者用初始化列表（冒号后面那一串）
初始化列表更高效——它是"直接构造"，而不是"先默认构造再赋值"
派生类怎么调用基类的带参构造函数 Python 
class Machine:
    def __init__(self, s):
        self.id = s                    # 基类负责装好自己的数据

class Robot(Machine):                  # ★ 括号里写基类名 = 继承
    def __init__(self, s, n):
        super().__init__(s)            # ★ 先请基类把 id 装好
        self.level = n                 # 再装自己的

r = Robot("R-01", 3)
print(r.id, r.level)                   # R-01 3
横线上该填 Machine(s)　 调用基类的构造函数，写法是"基类名(参数)"
注意　不能写 id(s)（那是成员变量，不是构造函数）； 也不能写 Machine::id(s)（那是在访问名叫 id 的成员）

4　封装

Encapsulation

4.1 把数据藏起来

把成员变量设成 private，对外只留方法 Python 
class Account:
    def __init__(self, b):
        self.__balance = b             # ★ 双下划线：把余额藏起来

    def deposit(self, x):
        if x > 0:                      # ★ 顺便做合法性检查
            self.__balance += x

    def getBalance(self):              # 查余额：只读接口
        return self.__balance

a = Account(100)
a.deposit(50)
print(a.getBalance())                  # 150
# print(a.__balance)   # ✘ 外面碰不到：名字被 Python 改过了
OUTPUT　150
封装的三个好处　 ① 外面改不了余额，只能走 deposit；
② 可以在方法里做检查（比如负数不让存）；
③ 内部怎么实现，外面不用知道

4.2 通过方法访问

封装的本质：给数据装一扇门。 数据藏在屋里（private）， 外面的人不许翻墙，只能从门（public 的方法）进出。
这样做的好处是：既然所有改动都要经过这扇门， 你就可以在门口设一个"检查员"—— 看看这次改动合不合理、要不要记录一笔。
而如果数据完全敞开（全 public）， 谁都能随手改，出了问题根本查不出是谁改的。
打个比方： 封装就像一台封闭的机器——内部齿轮怎么转，外面看不见； 但你给了几个接口（开关、进料口、出料口）。
你要它干活，就走接口；它内部怎么实现，你不需要知道，也不该去戳。
好处是：哪天它内部换了零件，只要你没改接口，用它的代码一行都不用动。

5　继承与多态

Inheritance & Polymorphism

5.1 继承：在蓝图上扩展

派生类自动拥有基类的成员 Python 
class Animal:                     # 基类（父类）
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(self.name, " 在吃东西")

class Cat(Animal):                # ★ 括号里写 Animal = 继承
    def meow(self):
        print(self.name, " 喵了一声")

c = Cat("小白")                    # ★ 连构造函数都是从 Animal 继承来的
c.eat()                           # ★ 继承来的
c.meow()                          # 自己新加的

# 结果：Cat 不用重写 name 和 eat，就都有了。
继承的好处　 共同的成员写在基类里，派生类只管加自己特有的部分——
不用重复写、改起来也只改一处

5.2 虚函数与多态

同一个调用，不同对象给出不同结果 Python 
class Animal:
    def speak(self):
        print("Animal ")

class Cat(Animal):
    def speak(self):              # ★ 重写了基类的方法
        print("Cat ")

class Dog(Animal):
    def speak(self):
        print("Dog ")

for a in (Animal(), Cat(), Dog()):
    a.speak()      # ★ 同一个 speak()，对象是谁就听谁的

# 输出：Animal / Cat / Dog —— 这就叫"多态"
OUTPUT　Cat
为什么不是 Animal？　 因为 speak 是虚函数——程序会在运行时看指针实际指向哪个对象， 然后调用那个对象自己的版本
这就叫"多态"：同一个调用，因对象不同而有不同表现
三句话理解多态： ① 基类的函数前面加 virtual， 它就变成了"虚函数"；
② 派生类里写一个同名、同参数的函数（可以标 override）， 这叫"重写"；
③ 用"基类指针/引用"去调用时， 程序会看它实际指的是哪个对象，去调那个对象的版本。
关键差别： 如果没有 virtual，编译时按"指针的类型"来定，输出的是基类版本； 有了 virtual，运行时按"实际对象的类型"来定。
两个非常容易考的"不能"： ① 构造函数不能是虚函数。 因为创建对象时，"到底要造哪个类"还没确定下来—— 虚函数的前提是"对象已经存在、才知道调用谁"，两者矛盾。
② 通过"基类指针"delete 派生类对象时，如果基类的析构函数"不是"虚函数， 派生类的析构函数就不会被调用。 正确做法是把基类的析构函数也写成 virtual。 （就像上面代码里的 virtual ~Animal() = default;）。
记忆：构造函数不能虚，基类析构要虚。

一个完整的类：构造、封装、方法 Python 
class Eagle:
    def __init__(self, n, s, h):      # ★ 构造函数：一出生就完整
        self.name = n
        self.speed = s
        self.hp = h

    def fly(self):
        if self.hp > 0:
            self.hp -= 5
            print(self.name, " 飞了一圈，血量 ", self.hp)
        else:
            print(self.name, " 已经飞不动了")

    def report(self):                 # 报告当前状态
        print(self.name, " 速度 ", self.speed, "，血量 ", self.hp)

a = Eagle("小灰", 80, 20)
b = Eagle("小白", 95, 10)

a.report()
a.fly()
b.fly()
b.report()
OUTPUT
小灰 速度 80，血量 20
小灰 飞了一圈，血量 15
小白 飞了一圈，血量 5
小白 速度 95，血量 5
小白 归巢了
小灰 归巢了
注意最后两行　析构顺序和创建顺序相反——后创建的 b 先销毁
和本单元的关系： 这个类把本单元的要点全都用上了。
① 封装：name、speed、hp 都是 private——外面拿不到，只能通过 fly() 和 report() 操作；
② 构造函数：用初始化列表一次把三个成员都设好， 保证对象一被造出来就是"完整可用"的状态；
③ const 成员函数：report() 只读不写，加 const 说明"我不会改自己"——这是个好习惯；
④ 析构函数：对象销毁时自动调用； 同一作用域里的多个对象，销毁顺序和创建顺序正好相反。

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
面向对象的坑，全在"能不能访问""调用哪一个"上。四条，前三条真题都考过。
1
以为"派生类可以直接访问基类的私有成员"。
扣哒鸭：private 连派生类都不给看。
基类里 private int value;，派生类里写 return value; —— 编译直接报错。
想让派生类能访问，得改成 protected； 或者由基类提供一个 public 的方法，派生类通过方法去读。
记牢：private 自己都不给派生类；protected 才给
2
以为"写了带参构造函数，编译器还会补一个无参的"。
扣哒鸭：只要你自己写了任何一个构造函数，编译器就不再生成默认的无参版本。
所以类里只有 Student(int x) 时，写 Student s; 会编译报错—— 找不到可以不带参数调用的构造函数。
解法：要么补一个无参构造，要么创建时把参数写上
3
漏了 virtual，多态不生效。
扣哒鸭：基类的函数前面必须写 virtual。
少了它，Animal *p = new Cat(); p->speak(); 会输出 Animal—— 因为编译器按"指针的类型"来决定了，而不是按对象实际是谁。
记牢：要多态就得 virtual
4
调用基类构造时写成 id(s) 或 Machine::id(s)。
扣哒鸭：调用基类构造函数的写法是"基类名(参数)"，也就是 Machine(s)。
Machine::id(s) 是在访问名叫 id 的成员， id(s) 更是在把成员变量当函数调——两个都不对。
正确写法：Robot(...) : Machine(s), level(n) {}

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
面向对象的错误，几乎都和"self 用没用对"有关。四条，条条都是新手必踩。
1
方法里忘了写 self。直接写 def attack():。
扣哒鸭：定义在类里的方法，第一个参数必须是 self， 否则调用时会报"多传了一个参数"。
注意：是"定义时"要写 self，"调用时"不用写。
正确写法：def attack(self, target):
2
访问属性时忘了 self。方法里直接写 hp = hp - damage。
扣哒鸭：不写 self. 的话，hp 只是个局部变量， 函数一结束就没了，对象上的血量根本没变。
必须写 self.hp = self.hp - damage。
正确写法：访问自己属性一律加 self.
3
把 __init__ 写成了 _init_ 或 init。
扣哒鸭：前后各是两个下划线：__init__。
写成别的名字，Python 就认不出它是初始化方法，造对象时不会自动执行， 属性也就设不上——而且不报错，特别难查。
正确写法：def __init__(self, ...):
4
把类当成对象直接用。直接写 Eagle.attack()。

云髓天阶的机器人要继承"机器"这个父类。下面代码的横线处填写哪一项，才能正确调用父类的带参数构造函数（　　）。
1  class Machine:

4
5  class Robot(Machine):
6      def __init__(self, s, n):
7          _______________
8          self.level = n

B.Machine.Machine(s)
C.super().__init__(s)
D.self.id = s
查看答案与详解
答案：C。子类要调用父类的构造方法，标准写法就是 super().__init__(参数…)。
为什么用 super()？它的意思是"交给父类去初始化那一部分"，这样父类的初始化代码不用重写、也不会漏掉；而且以后父类改名或换继承关系，这行代码照样正确 —— 这就是"多态/可维护"的好处。
A 错：Machine(s) 是在创建一个新的 Machine 对象，跟当前这个 Robot 对象毫无关系；
B 错：这种写法在 Python 里要传 self 才可能工作，且不是规范写法；
D 错：虽然赋值结果"看着像"，但绕过了父类的初始化逻辑 ——父类以后加了别的初始化动作就会漏做。
记这一条就够：子类构造函数第一行写 super().__init__(…)。

原创练习题编程题
题目要求：定义一个类 Robot， 属性有名称与电量（初始 100）；方法有 work()（每次消耗 20 电量） 和 charge()（把电量补满）。创建两个机器人，各做不同次数的操作并输出电量。
查看参考答案与要点 
class Robot:
    def __init__(self, name):
        self.name = name
        self.power = 100          # 初始电量

    def work(self):
        self.power = self.power - 20
        print(self.name, "干活，剩余电量", self.power)

    def charge(self):
        self.power = 100
        print(self.name, "充满电")

r1 = Robot("小铁")
r2 = Robot("小钢")

r1.work()
r1.work()
r1.charge()
r2.work()

print(r1.power, r2.power)

输出：小铁干活 80、小铁干活 60、小铁充满电、小钢干活 80，最后 100 和 80
要点：
① __init__ 里用 self.name = name 把参数存成属性；
② 所有方法第一个参数都写 self，访问属性加 self.；
③ 两个对象互不干扰：r1 充电不影响 r2；
④ 调用方法时不用写 self，只传真正的参数（本例没有额外参数）。
对应小节3 属性与方法；4 init 与 self。

9　本单元小结

Unit Summary
贺舒曼 · 镜中先知
三句话记住面向对象：
一、类 = 图纸，对象 = 照图纸造出的实物。
二、属性是"它有什么"，方法是"它能做什么"，都用 self 访问。
三、__init__ 在造对象时自动执行，用来初始化属性。
最容易错的一点我也说了：定义方法要写 self，调用方法不要写。

你在造物工坊收获了什么

  • 面向对象——把"数据"和"操作数据的动作"打包成一个模板。
  • 类与对象——类是图纸，对象是照图纸造出的实例，各对象的属性互相独立。
  • 属性——对象"有什么"，如 self.name、self.hp。
  • 方法——对象"能做什么"，如 def attack(self):。
  • self——方法的第一个参数，代表"当前这个对象"；调用时不用写。
  • __init__——对象出生时自动执行，前后各两个下划线，用来准备初始属性。
  • 与字典的对照——eagle["hp"] 与 eagle.hp 类似；但类还能把方法一起打包。
