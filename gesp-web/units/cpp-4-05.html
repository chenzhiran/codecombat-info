1　参数是怎么传进去的

Pass by Value

1.1 值传递：递的是复印件

先把最常见的疑问说清楚：函数里改了形参，外面的实参会不会跟着变？

答案是：不会 C++ 
#include <iostream>
using namespace std;

void change(int x) {        // x 是形参
    x = 20;                 // 改的只是函数里面的 x
    cout << "函数里：" << x << endl;
}

int main() {
    int x = 10;
    change(x);              // 把 x 的"值"复制一份传进去

    cout << "函数外：" << x << endl;
    return 0;
}
OUTPUT　函数里：20　/　函数外：10
看明白了吗　函数里的 x 是"另一个变量"，改它完全不影响外面

1.2 一条实用结论

打个比方： 传参数就像把东西交给别人，交的东西不同，结果完全不同：
数字、字符这些"不可变对象"——相当于你抄了一串号码给他，他改自己那张纸，你手里那张还是原样；
数组这些"可变对象"——相当于你把屋子钥匙给了他，他在屋里挪动了家具，你回去一看也变了。
一句话：不可变对象"改了外面不变"，数组"改了外面会变"。
一条实用结论： C++ 的普通参数（int、double、char 等）都是"值传递"—— 函数里怎么改，外面都不变。
想让函数真的改到外面的变量，只有两条路： ① 传指针（上一单元学过）；② 传引用（本单元第 4 节要学）。

2　传递数组与改内容

Passing Arrays

2.1 数组作为参数

数组是个例外——它被传进函数时，函数里改了，外面真的会变。

数组传进去，改的是"原件" C++ 
void doubleAll(int a[], int n) {     // 数组参数
    for (int i = 0; i < n; i++) {
        a[i] *= 2;                   // 改的是原数组
    }
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    doubleAll(a, 5);                 // 传数组名 + 长度

    for (int i = 0; i < 5; i++) cout << a[i] << " ";
    cout << endl;
    return 0;
}
OUTPUT　2 4 6 8 10
为什么这次会变？　因为数组名本身就是"首元素的地址"—— 传进去的是地址，函数通过地址找到的就是原数组
为什么数组是例外？ 回想上一单元学过的一句话：数组名相当于"第一个元素的地址"。
所以"把数组传给函数"，实际上传的是"数组在哪儿"， 而不是"把整个数组复制一份"。
函数顺着这个地址去改，改的自然就是原数组。
这也顺便说明了一件事：数组参数其实是一种隐式的"指针传递"。
数组参数的一个"坑"：长度会丢失。 在函数里写 sizeof(a) / sizeof(a[0]) 是算不出元素个数的！
因为在函数内部，a 已经"退化"成了一个指针， sizeof(a) 得到的是一个指针的大小（通常是 8 字节），不是整个数组的大小。
所以传数组时，必须额外把长度一起传进去—— 就像上例里的 doubleAll(a, 5)。

2.2 改内容还是重新赋值

一个容易搞混的区别 C++ 
void f1(int a[]) {          // 改"内容" → 外面会变
    a[0] = 100;
}

void f2(int a[]) {          // 把 a 指向别处 → 外面不变
    int b[3] = {9, 9, 9};
    a = b;                  // 只是让本地这个 a 换了个目标
}

int main() {
    int a[3] = {1, 2, 3};
    f1(a);                  // a[0] 变成 100
    cout << a[0] << endl;     // 100

    f2(a);                  // a 完全没动
    cout << a[0] << endl;     // 100
    return 0;
}
OUTPUT　100 / 100
关键区分　 改"地址指向的内容"（a[0] = 100）→ 外面会变；
改"地址本身"（a = b）→ 只是本地这个变量的目标换了，外面不受影响

3　变量作用域

Scope

3.1 局部变量与全局变量

接下来是另一个核心问题：一个变量在哪些地方"看得见"？

两种变量，两种可见范围 C++ 
int g = 100;                // ★ 全局变量：定义在所有函数外面

void show() {
    cout << g << endl;       // 100  函数里也能看见全局变量
}

int main() {
    int a = 10;             // ★ 局部变量：定义在函数里面
    cout << a << endl;       // 10
    cout << g << endl;       // 100

    show();
    // cout << a;           // 别的函数里看不见 main 的 a
    return 0;
}
OUTPUT　10 / 100 / 100
可见性　全局变量"哪里都看得见"；局部变量"只有自己那个函数（及里面）看得见"

3.2 三条铁律

三条铁律： ① 局部变量只在它所在的那对大括号里有效——出了 {} 就"消失"了。
② 全局变量在整个程序里都看得见——但函数里如果定义了同名局部变量，会"盖住"全局的（这叫遮蔽）。
③ 局部变量的生命周期：函数执行时诞生，函数返回时销毁。
这就解释了上一条的现象：函数里的 x 在函数返回后就没了，所以外面那个 x 当然没变。
同名时会怎样？ C++ 
int x = 100;                // 全局

void f() {
    int x = 5;              // 局部（遮蔽了全局那个）
    cout << "函数里：" << x << endl;
}

int main() {
    f();                    // 函数里：5
    cout << "main 里：" << x << endl;
    return 0;
}
// 输出：函数里：5   /   main 里：100
OUTPUT　函数里：5 / main 里：100
注意　函数里的 x 是"自己的局部变量"，和全局的 x 是两个不同的变量

4　引用参数

Reference Parameters

4.1 引用 & 是什么

如果确实想让函数改到外面的变量，除了传指针，C++ 还提供了更清爽的写法：引用。

参数前面加一个 &，就变成了"别名" C++ 
void change(int &x) {       // ★ 注意这个 &
    x = 20;                 // 改的是"外面那个 x 本人"
}

int main() {
    int x = 10;
    change(x);              // 调用时照常写，不用加 &
    cout << x << endl;        // 20   ← 这次真的变了！
    return 0;
}
OUTPUT　20
对比记忆　 形参写 int x → 值传递，改不到外面；
形参写 int &x → 引用传递，改的就是外面那个变量
引用是什么？ 引用就是给一个已有变量再起一个名字（别名）。
就像一个人既有大名又有小名——喊哪个都是在喊他本人。
int &r = x; 之后，r 和 x 就是同一个变量， 改 r 就是改 x。
所以"引用参数"传进去的不是副本，而是"本人"。

4.2 什么时候该用引用

参数写法含义什么时候用
void f(int x)值传递（副本）只是"读一读"这个值
void f(int &x)引用传递（本人）需要修改调用者的变量
void f(const int &x)常引用不修改但想省一次复制（大对象效率更高）
void f(int *x)指针传递需要在函数里"换目标"或处理数组
建议：优先用引用，别用全局变量。 很多人遇到"函数改不到外面"的问题时，第一反应是把变量改成全局的。
这样虽然能跑通，但很糟糕——因为全局变量任何函数都能随手改它， 出了问题极难排查。
正确做法：需要修改就用引用参数 &， 把"谁改了它"这件事写在函数的参数表上，一眼就能看出来。

引用参数：让函数把结果带回来 C++ 
#include <iostream>
using namespace std;

// 统计数组里的最大值、最小值和总和
void stat(int a[], int n, int &mx, int &mn, int &sum) {
    mx = a[0];
    mn = a[0];
    sum = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] > mx) mx = a[i];
        if (a[i] < mn) mn = a[i];
        sum += a[i];
    }
}

int main() {
    int a[5] = {12, 7, 25, 3, 18};
    int mx, mn, sum;

    stat(a, 5, mx, mn, sum);        // 三个结果一次性带回来

    cout << mx << " " << mn << " " << sum << endl;
    return 0;
}
OUTPUT　25 3 65
为什么必须用引用？　因为 return 一次只能交回一个值， 而这里要带回三个——引用参数正好解决了这个问题
和本单元的关系： "一个函数要带出多个结果"是引用参数最典型的用途。
回想上一课说过：return 只能交回一个值。 那要带回三个怎么办？用引用参数把"输出的位置"传进去。
这也是竞赛里很常见的写法——参数列表里带 & 的那些，往往就是"用来装结果的"。

6　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
这一课只有一个核心概念，但极容易错。四条。
1
以为"函数里改了形参，外面就会变"。
扣哒鸭：void change(int x) { x = 20; } 调用之后， 外面的变量一点没动。
因为 C++ 的普通参数是值传递——改的是副本。
要改外面：形参加 &（引用）或传指针
2
在函数里用 sizeof 求数组长度。
扣哒鸭：数组一传进函数，就退化成一个指针了。
sizeof(a) 得到的是指针大小（8 字节），不是整个数组的大小。
所以长度必须当成参数一起传进去。
正确做法：void f(int a[], int n)
3
以为 a = b 能把外面的数组换掉。
扣哒鸭：a[0] = 100 改的是内容，外面会变；
a = b 改的是地址，只是让本地这个 a 换了目标——外面完全不受影响。
区分：改内容会生效，改地址不会
4
函数里定义了和全局变量同名的局部变量，还以为改的是全局的。
扣哒鸭：函数里写 int x = 5;， 这是新造了一个局部变量，把全局的 x "遮住"了。
你在函数里改来改去，动的都是自己那个 x，全局的纹丝不动。
避免：别给局部变量起和全局一样的名字

Practice

前 2 题改编自 C++ 四级真题，其余为原创练习题。

改编自 2026 年 9 月 · C++ 四级 · 判断题 第 4 题判断题
执行下面程序后会输出 20。（　　）
void change(int x) { x = 20; }
int main() {
    int x = 10;
    change(x);
    cout << x;
    return 0;
}
查看答案与详解
答案：错误（×）。输出是 10。
执行过程：
① int x = 10; —— 外面的 x 是 10；
② change(x) —— 把 x 的值 复制一份给形参， 函数里的 x 是另一个变量；
③ 函数里 x = 20 —— 改的是副本； 函数返回后，副本被销毁；
④ 外面的 x 从头到尾都是 10。
要让输出变成 20，只需把形参改成引用： void change(int &x) { x = 20; }—— 加一个 &，结果就从 10 变成 20。
对应小节1.1 值传递：递的是复印件；4.1 引用 & 是什么。
改编自 2026 年 6 月 · C++ 四级 · 判断题 第 6 题判断题
对于按升序实现的稳定插入排序，移动元素的条件通常应为 a[j] >= key，这样能够保证相等元素的相对顺序不变。（　　）
查看答案与详解
答案：错误（×）。这里的关键判据是：遇到"和 key 相等"的元素，到底该不该把它往后挪？
如果条件写 a[j] >= key：遇到相等的元素也会把它往后挪一位， 于是 key 最终被插到了相等元素的前面—— 原来的先后顺序被颠倒了，这叫"不稳定"。
要保证稳定，条件应该写 a[j] > key（不带等号）—— 遇到相等的就停下来，key 插在它们后面，顺序就保住了。
一句话记牢：想让排序稳定，比较时就不要带等号。
对应小节本页之外的排序思想（第 7 单元会详细讲）。
原创练习题单选题
执行下面的代码，输出是（　　）。
int g = 100;
void f() {
    int g = 5;
    cout << g << " ";
}
int main() {
    f();
    cout << g << endl;
    return 0;
}
A.100 100　　B.5 100　　C.5 5　　D.编译错误
查看答案与详解
答案：B。这是典型的"局部变量遮蔽全局变量"：
① 函数 f 里：写了一句 int g = 5;， 这就是新造了一个局部变量 g，它把全局的 g "遮住"了。 所以在 f 里输出的是 5。
② main 里：没有定义局部 g，所以用的是全局那个 g，输出 100。
关键理解：这是两个完全不同的变量，只是碰巧同名。 函数里的那个，函数一返回就销毁了。
C 项是误以为函数里改的是全局变量。
实际开发建议：别给局部变量起和全局变量一样的名字，很容易看错。
对应小节3.2 三条铁律。
原创练习题判断题
把数组作为参数传给函数，函数里修改了数组元素，调用处的原数组也会跟着改变。（　　）
查看答案与详解
答案：正确（√）。这是值传递的一个例外。
原因：数组名本身相当于"第一个元素的地址"。 所以"把数组传给函数"，实际传的是地址，而不是把整个数组复制一份。
函数顺着这个地址去操作，改的自然就是原数组。
但不能混淆的是：
✅ 改内容（a[0] = 100）→ 外面会变；
❌ 改地址（a = b）→ 只是本地这个 a 换了目标，外面不受影响。
另外要提醒：数组参数会"丢掉长度"， 函数里 sizeof 算不出元素个数，必须额外传一个长度参数。
对应小节2.1 数组作为参数；2.2 改内容还是重新赋值。
原创练习题单选题
要让函数真正修改调用处的变量，下面哪种形参写法可行（　　）。
A.void f(int x)
B.void f(int &x)
C.void f(const int x)
D.以上都可以
查看答案与详解
答案：B。int &x 是引用参数—— 形参成了实参的别名，函数里改它，就是改外面那个变量本人。
A 错：int x 是值传递，改的是副本。
C 错：const int x 只是说"这个副本在本函数里不能改"， 它本身还是副本，完全改不到外面。
补充：传指针 void f(int *x) 配合 *x = 20 也能做到， 那是上一单元学过的另一条路。

原创练习题编程题
题目要求：写一个函数 void divide(int a, int b, int &q, int &r)， 计算 a ÷ b 的商和余数，并通过引用参数带回去。 在 main 里读入 a、b 并输出结果。
查看参考答案与要点 
#include <iostream>
using namespace std;

void divide(int a, int b, int &q, int &r) {
    q = a / b;          // 商：直接写进引用的位置
    r = a % b;          // 余数
}

int main() {
    int a, b;
    cin >> a >> b;

    int q, r;
    divide(a, b, q, r);         // q、r 被"填上"结果

    cout << q << " " << r << endl;
    return 0;
}

输入 17 5 输出：3 2
要点：
① return 只能带出一个值，而这里要带回两个—— 引用参数是最省事的办法；
② q、r 是引用参数（带 &）， 函数里给它们赋值，就等于给 main 里的 q、r 赋值；
③ a、b 是普通参数（值传递）， 因为它们只需要被读，不需要被改——该不该加 & 要看"是否要改"。；
④ 调用时不用写 &， 写成 divide(a, b, q, r) 就行——引用在语法上就当普通变量用。

8　本单元小结

Unit Summary
安雅 · 红发队长
四句话记住这一课：
一、C++ 的普通参数是"值传递"——传进去的是副本，函数里怎么改都不影响外面。
二、数组是例外——传的是地址，所以函数里改内容，外面会变；但改地址不会。
三、局部变量只在它那对 {} 里有效，全局变量哪里都看得见；同名时局部会遮住全局。
四、想让函数真的改到外面，就加一个 & 变成引用；别图省事去用全局变量。
管子看透了。下一站是齿轮传动链——那里每一环都从上一环推出来，一环扣一环。

你在参数输送管旁收获了什么

  • 值传递——普通参数传的是副本；函数里改形参，外面不变。
  • 数组是例外——数组名相当于地址，函数里改内容，外面会变。
  • 数组参数会丢长度——函数里 sizeof 算不出元素个数，要额外传长度。
  • 改内容 vs 改地址——改 a[0] 会生效；改 a = b 不会。
  • 局部变量——定义在函数（或 {}）里，出了大括号就消失。
  • 全局变量——定义在所有函数外面，哪里都看得见；函数返回后依然存在。
  • 遮蔽——局部变量和全局同名时，函数里用的是局部的那个。
  • 引用——int &r = x; 让 r 成为 x 的别名，改 r 就是改 x。
  • 引用参数——形参写 int &x，函数里改的就是外面那个变量；调用时不用加 &。
  • 引用的典型用途——一个函数要带出多个结果时（因为 return 只能带一个）。
  • 工程建议——需要修改就用引用参数，别用全局变量。
