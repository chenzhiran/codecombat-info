1　注释：写给人的话

Comments

1.1 两种注释写法

怎么用注释 C++ 
#include <iostream>
using namespace std;

int main() {
    int n;                      // 单行注释：写在语句后面
    cin >> n;

    /* 下面是计算部分
       这里可以写好几行说明 */
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += i;               // 累加
    }

    cout << sum;
    return 0;
}
要点　注释里的内容可以随意写中文、英文、符号——编译器完全不理它

1.2 注释有什么用

作用说明
说明意图告诉别人（和三个月后的自己）这段代码在干什么
标记待办用 // TODO: 记下"这里以后要改"
临时屏蔽把暂时不想执行的一段代码注释掉，方便调试
方便协作多人共同开发时，注释就是沟通的桥梁
打个比方： 注释就是沿途的发光路标。
它从来不会帮你多走一步路——路还是那条路，走路的是你的脚；
但等你半夜回来、或者换个人来走的时候，是这些路标告诉你"前面是桥""左边有坑"。
写注释，就是给未来的自己（和同伴）留一盏灯。
注释的"黄金标准"： 解释"为什么这么做"，而不是"这一行在做什么"。
sum += i; // 把 i 加到 sum 上 —— 这种注释没意义，代码本身就说明了；
sum += i; // 累加 1 到 n，用于求平均值 —— 这种才有价值。

1.3 注释的三个注意点

打个比方： 多行注释像一只没有拉链、只有"打开"和"合上"两句话的袋子。
你刚说"合上"，袋子就真的合上了——里面再写"打开"它也不会理你。
所以 /* */ 里面不能再套一对 /* */；真要写好几段说明，就用 // 一行一行写。
① 多行注释不能嵌套：
/* 外层 /* 内层 */ 还在外层吗？ */ —— 程序在第一个 */ 处就认为注释结束了， 后面的内容会被当成代码，导致报错。
所以不要在 /* */ 里再写一对 /* */。
② 注释里可以随便写中文和英文：
注释文本中间不能混用中英文这句话是错的。
注释是给编译器"跳过"的，里面写什么语言、什么符号都不会报错。
真正不能混中英文的是"代码部分"——比如中文的分号、括号、引号。
③ 注释不会让程序变快或变慢：
注释在编译阶段就被丢掉了，运行时完全不存在。
所以多写注释不会影响程序性能，只会让代码更好懂。

2　读懂程序的"抱怨"

Understanding Errors

2.1 三类错误

打个比方： 把写程序想成出发去远行，出错有三种情况：
① 编译错误——出门前发现行李没打包好，连门都出不了。好在有人会告诉你"少了什么"。
② 运行错误——出了门，走到半路车坏了，直接停在原地。
③ 逻辑错误——一路顺顺利利到了终点，却发现来错了地方，全程没有任何报警。
三种里最麻烦的是第三种，只能靠自己一步步核对。
一句话分清三类错误：
编译错误——根本过不了编译，会告诉你第几行。
运行错误——编译能过，跑起来崩。
逻辑错误——能跑、但结果是错的，没有任何提示，最需要调试能力。

2.2 最常见的五种编译错误

错误错误示例怎么改
少分号int a = 5补上 ;
括号 / 引号不配对cout << (a + b;补齐另一半
变量没有声明直接写 x = 5;先写 int x;
用了中文标点cout << "你好"；换成英文半角符号
格式符与类型不匹配printf("%d", 3.5);小数改用 %f
特别提醒：% 只能用于整数。
写 2.5 % 2，编译阶段就会报错——它不会先生成可执行文件再运行出错。
所以"这段代码能生成可执行文件，只是运行时报错"这类说法，往往是错的。

2.3 怎么读错误信息

编译器其实在告诉你怎么改 C++ 
main.cpp: In function 'int main()':
main.cpp:7:12: error: expected ';' before 'cout'
    7 |     int a = 5
      |            ^
      |            ;
main.cpp:9:18: error: 'b' was not declared in this scope
    9 |     cout << a + b;
读法　main.cpp:7:12 = 文件名、第 7 行、第 12 个字符处；
expected ';' before 'cout' = "在 cout 前面应该有个分号"——它甚至告诉你缺的是什么
读错误信息的三个技巧：
① 只看第一条错误。后面的一堆往往是"连锁反应"，改完第一条就全消失了。
② 先看行号，再去那一行找。但要注意：错误常常在报错行的"上一行"（比如上一行忘了分号）。
③ 看关键词。expected（缺少什么）、undeclared（没声明）、 unmatched（不配对）——这几个词最常见。

3　调试：把错误找出来

Debugging

3.1 输出中间变量

"打印大法"：最朴素也最好用 C++ 
int sum = 0;
for (int i = 1; i <= 5; i++) {
    sum += i;
    cout << "第 " << i << " 轮：sum = " << sum << endl;   // ★ 调试语句
}

cout << "最终结果：" << sum;
OUTPUT
第 1 轮：sum = 1
第 2 轮：sum = 3
第 3 轮：sum = 6
第 4 轮：sum = 10
第 5 轮：sum = 15
最终结果：15
打个比方： 调试就像夜雾里走夜路。整条路都黑着，你根本看不出哪一段有问题。
这时候你每隔几步点一盏灯——灯亮到哪一段，你就知道前面的路是对的；
一旦某两盏灯之间是黑的，问题一定就在那一段里。
所以"打印中间变量"就是点灯：在关键位置把变量的值打出来，看它是在哪一步开始不对的。
为什么"打印大法"最有效？ 因为你能亲眼看见变量每一步的变化。
如果某一轮的值突然不对，那问题就在这一步附近。
调试完记得把这些打印语句删掉或注释掉——正式提交的代码不该有多余输出。

3.2 缩小范围

方法怎么做适合
打印中间变量在关键位置输出变量的值不知道哪一步开始出错
注释掉一半先把后半段注释掉，看前半段对不对代码很长、错误范围不明
用小数据手算拿 n = 3 这样的小输入，自己先算一遍答案逻辑错误
对照已知答案换几种输入，比较程序输出和手算结果结果"差不多但不对"
再打个比方： "把后半段先注释掉"，就像查一条坏掉的灯笼长廊——
先把后半段的灯全灭了，只看前半段亮不亮。前半段亮，问题就在后半段；前半段也不亮，问题就在前面。
每查一次，可疑范围就缩小一半。这比从头一行行看快得多。

3.3 检查清单

扣哒鸭的五步检查清单：
① 符号——分号、括号、引号是否齐全？有没有中文标点？
② 声明——用到的变量都声明了吗？类型对吗？
③ 边界——循环是 < 还是 <=？数组下标从 0 还是 1 开始？
④ 初始值——累加变量初始化成 0 了吗？
⑤ 输出格式——空格、换行、小数位数和题目要求一致吗？
按这个顺序过一遍，八成的错误都能揪出来。

4　综合项目：鸡兔同笼

Chickens & Rabbits

4.1 分析问题

题目： 笼子里有鸡和兔。头一共 tou 个，脚一共 jiao 只。 问鸡和兔各有多少只？
已知：鸡有 2 只脚，兔有 4 只脚。

这道题看起来要用方程，但用程序做，有一个更简单也更通用的办法：枚举。

枚举思路：把所有可能都试一遍 C++ 
假设兔有 tu 只，那么：
    鸡就有 (tou - tu) 只
    脚的总数就是 tu * 4 + (tou - tu) * 2
    如果这个数正好等于 jiao —— 找到了！

让 tu 从 0 一直试到 tou，每个都验算一遍就行。
枚举法　不猜、不推，把所有可能逐个试一遍——这是计算机最擅长的事
打个比方： 枚举法就是"一个一个试"——
假设兔子有 0 只，算一下脚够不够；不够？那就假设有 1 只；再不够？假设 2 只……
一直试到脚数正好对上，或者试完所有可能都不对（那就无解）。
这种"笨办法"看着不聪明，却是计算机最擅长、也最不容易出错的办法——因为它不知疲倦。

4.2 用枚举求解

枚举法为什么好用？ 因为计算机最擅长的就是"重复做同一件事"。
只要把"验证一种可能"写成几行代码，再套一个循环，就是完整的解法。
一级的所有综合题，基本都能用"枚举 + 判断"解决。

4.3 完整程序

鸡兔同笼 · 完整解法 C++ 
#include <iostream>
using namespace std;

int main() {
    int tou, jiao;
    cin >> tou >> jiao;

    int tu, ji;

    // 枚举兔的只数：从 0 试到 tou
    for (tu = 0; tu <= tou; tu++) {
        ji = tou - tu;                       // 剩下的都是鸡
        if (tu * 4 + ji * 2 == jiao) {       // 脚数对得上吗？
            cout << "兔：" << tu
                 << " 鸡：" << ji << endl;
            break;                           // 找到就跳出
        }
    }

    // 循环正常结束（没 break）说明没找到
    if (tu == tou + 1) {
        cout << "无解" << endl;
    }

    return 0;
}
输入　8 22　　输出　兔：3　鸡：5
验算：3 + 5 = 8 个头；3 × 4 + 5 × 2 = 12 + 10 = 22 只脚 ✔
"有没有找到"怎么判断？ 这是本题最容易写错的地方。两种稳妥写法：
① 用循环变量的最终值判断——条件写成 tu <= tou， 循环正常结束时 tu 一定等于 tou + 1；如果是 break 跳出的，tu 就小于 tou + 1。
② 用一个标记变量——开头写 bool found = false;， 找到时改成 true，最后判断 if (!found)。
如果条件写成 tu < tou + 1（等价于 <= tou）， 那正常结束时 tu 等于 tou，判断就要改成 tu == tou——两处必须配套，不能只改一处。

6　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
最后四条。它们不光是这一单元的坑，更是这一整级最容易丢分的地方。
1
以为"注释里不能混中英文"。
扣哒鸭：注释是给编译器跳过的内容， 里面写什么语言、什么符号都不会报错。
真正不能用中文的是代码部分的标点——比如中文的分号和引号。
正确认识：注释随便写；代码必须用英文半角符号
2
把"编译错误"说成"运行时报错"。
扣哒鸭：2.5 % 2 这种写法根本编译不过， 不会生成可执行文件，也就谈不上"运行时出错"。
看清楚题目问的是哪一类错误。
正确认识：编译不通过 → 编译错误，不是运行错误
3
循环条件与"是否找到"的判断不一致。
扣哒鸭：循环写 tu < tou 时，正常结束 tu 等于 tou；
写 tu <= tou 时，正常结束 tu 等于 tou + 1。
循环条件和后面的判断必须配套，改一处就要改另一处。
建议：用 bool found 标记变量，最不容易错
4
调试用的打印语句忘了删。
扣哒鸭：调试时加的 cout 很管用， 但提交前一定要删掉或注释掉。
多出来的那一行输出，会让判题系统判定"答案错误"。
正确做法：调试语句用注释包裹，方便随时开关

7　题目练习

Practice

前 4 题改编自 C++ 一级真题，其余为原创练习题。

改编自 2026 年 6 月 · C++ 一级 · 第 2 题单选题
在使用集成开发环境编辑源代码文件时，程序员经常需要在编辑区对代码做各种修改。 以下关于编辑区操作的描述，不正确的是（　　）。
A.可以将变量名 count 统一修改为 number
B.可以连续撤销最近若干次输入的内容
C.可以调整代码行的缩进（如按 Tab 键）
D.在注释文本中间不能混用中英文
查看答案与详解
答案：D。注释的作用是给人看、给编译器跳过， 里面写中文、英文、甚至符号都可以，不存在"不能混用中英文"的限制。
A、B、C 都是 IDE 编辑区的正常功能：批量替换、撤销、缩进。
要小心区分：注释里可以随便写，但代码部分的标点必须是英文半角。
对应小节1.3 注释的三个注意点。
改编自 2026 年 6 月 · C++ 一级 · 判断题 第 7 题判断题
C++ 代码 cout << (2.5 % 2) 能够生成可执行代码， 但执行时将报错，因为 % 只能适用于正整数。（　　）
查看答案与详解
答案：错误（×）。取余运算符 % 的操作数必须是整数， 2.5 是小数——编译器检查到类型不合法，直接报错，根本生成不了可执行文件。
所以这句话错在两处：一是它"不能生成可执行代码"，二是它也谈不上"运行时才报错"。
记住：类型不匹配属于编译错误。
对应小节2.1 三类错误；2.2 最常见的五种编译错误。
改编自 2026 年 9 月 · C++ 一级 · 判断题 第 8 题判断题
在 C++ 代码中，如果两个变量都只包含下划线 _， 但数目不同，则可能导致编译器无法识别，而报告变量重复定义。（　　）
查看答案与详解
答案：错误（×）。C++ 里的标识符是逐字符比较的：
_、__、___ 是三个完全不同的名字，不会互相冲突，编译器能清楚地区分它们。
顺带提醒：以两个下划线开头、或以下划线加大写字母开头的名字是保留给编译器用的， 自己命名时最好避开。
对应小节2.1 三类错误。
改编自 2026 年 6 月 · C++ 一级 · 判断题 第 9 题判断题
如果 a 是 C++ 的整型变量，值为 4， 则表达式 (a % 2 == 0) + (a / 2) 的值为 4。（　　）
查看答案与详解
答案：错误（×）。分开算两部分：
① a % 2 == 0：4 % 2 = 0，0 == 0 成立 → 值为 1（关系运算的结果是 1 或 0）；
② a / 2：4 / 2 = 2（整数除法）。
所以整个表达式的值是 1 + 2 = 3，不是 4。
这道题同时考了三个点：取余、关系运算的结果、整数除法。
对应小节2.1 三类错误（这属于"能跑但结果不对"的逻辑错误）。
原创练习题单选题
下列 C++ 注释的写法中，会出错的是（　　）。
A.// 这是单行注释
B.int a = 5; // 给 a 赋值
C./* 外层 /* 内层 */ 还在注释里吗 */
D./* 多行 注释 写完 */
查看答案与详解
答案：C。多行注释不能嵌套。
程序读到第一个 */ 就认为注释结束了， 于是"还在注释里吗"和最后的 */ 会被当成代码，导致编译错误。
A、B、D 都是合法写法。
对应小节1.3 注释的三个注意点。
原创练习题单选题
下面这段 C++ 代码的问题是（　　）。
int i;
for (i = 1; i <= 5; i++)
    cout << i << " ";
cout << "结束";
A.会编译错误
B.可以正常运行，输出 1 2 3 4 5 结束
C.会死循环
D.只输出一个 1
查看答案与详解
答案：B。这里的 for 没有花括号， 它只管紧随其后的第一条语句，也就是 cout << i << " ";。
而 cout << "结束"; 在循环之外，循环结束后才执行一次。
所以输出是 1 2 3 4 5 结束——结果是对的，只是写法容易让人误会。
但要注意：如果本意是"每一轮都输出结束"，那就必须加花括号。
对应小节3.3 检查清单。
改编自 2026 年 9 月 · C++ 一级 · 编程题 · 鸡兔同笼编程题
题目要求：读入头总数 tou 和脚总数 jiao， 输出兔和鸡的只数；若无解则输出 无解。
样例：输入 8 22，输出 兔：3 鸡：5。
查看参考答案与要点 
#include <iostream>
using namespace std;

int main() {
    int tou, jiao;
    cin >> tou >> jiao;

    int tu, ji;
    bool found = false;                  // ★ 标记变量

    for (tu = 0; tu <= tou; tu++) {
        ji = tou - tu;
        if (tu * 4 + ji * 2 == jiao) {
            cout << "兔：" << tu
                 << " 鸡：" << ji << endl;
            found = true;
            break;                       // 找到就跳出
        }
    }

    if (!found) {
        cout << "无解" << endl;
    }

    return 0;
}

输入 8 22 输出：兔：3 鸡：5；输入 10 25 输出：无解
要点：
① 枚举思路：把兔的只数从 0 试到 tou，逐一验算脚数；
② 用 bool found 标记"有没有找到"， 比依赖循环变量的最终值更稳妥（循环条件改了也不受影响）；
③ 找到之后立刻 break，不必继续试；
④ 判断条件 tu * 4 + ji * 2 == jiao 用的是两个等号；
⑤ 输出格式要严格和题目一致——冒号、空格都不能随意改。
对应小节4 综合项目：鸡兔同笼。

8　本单元小结

Unit Summary
安雅 · 红发队长
三句话记住这一单元：
一、注释用 // 或 /* */，给人看、给机器跳过，不能嵌套。
二、错误分三类：编译错误（过不了）、运行错误（一跑就崩）、逻辑错误（结果不对）。
三、调试最实用的办法：把中间变量打印出来，亲眼看着它变。
一级到这里就结束了。往前看，你会走得更远。

你在迷雾中学到了什么

  • 注释——// 单行、/* */ 多行；不影响运行。
  • 注释不能嵌套——第一个 */ 就结束了。
  • 注释里可以随便写——中英文混用完全没问题；受限的是代码部分的标点。
  • 编译错误——过不了编译，会告诉你行号；如少分号、中文标点、类型不匹配。
  • 运行错误——编译过了但一跑就崩；如除以 0。
  • 逻辑错误——能跑但结果不对，没有任何提示，最需要调试。
  • 调试方法——打印中间变量、注释掉一半、用小数据手算对照。
  • 检查清单——符号 → 声明 → 边界 → 初始值 → 输出格式。
  • 枚举法——把所有可能逐个试一遍，是计算机最擅长的事。
  • 鸡兔同笼——循环枚举兔的只数，验算脚数；用标记变量判断有没有解。

9　C++ 一级总复习

Level 1 Review
考点必须掌握的一句话
计算机组成输入设备、运算器、控制器、存储器、输出设备；运算器与控制器合称 CPU
四代计算机划分依据是核心元器件
程序与语言只有机器语言能被直接执行；C++ 是编译型的高级语言
IDE能编辑、编译、运行、调试，但不能直接控制硬件
变量必须先声明类型才能使用；int b = a; 之后改 a 不影响 b
数据类型int、long long、double、char、bool
字符与字符串字符用单引号 'A'，字符串用双引号 "A"
常量const 定义时必须赋值，之后不能改
整除整数 ÷ 整数 = 整数；7 / 2 = 3、8 / 10 = 0
取余n % 2 判奇偶、n % 10 取个位；% 只能用于整数
自增自减++b *= 2 + 1 要分三步读：先自增、再算右边、最后复合赋值
关系运算结果是 1 或 0，可以当数字参与运算
优先级括号 → 一元 → 乘除余 → 加减 → 关系 → 逻辑 → 赋值；同级从左往右
输出cout << 或 printf；格式串里非 % 的字符原样输出
输入cin >> 或 scanf（变量前要加 &）；cin 按类型读，遇非法字符就停
换行endl、"\n"、printf("\n") 三者等价
分支if 只管第一条语句；括号后不加分号；判断相等用 ==
多分支else if 从上往下判断，一成立就跳出，按"由严到宽"排
循环三要素：起点、条件、推进；少了推进会死循环
循环结束后的 i是"第一个让条件不成立的值"，如 i < 10 结束时 i = 10
break / continuebreak 整个退出，continue 只跳过这一轮；它后面的代码是死代码
注释// 与 /* */；不能嵌套；不影响运行
三类错误编译错误（过不了）、运行错误（一跑就崩）、逻辑错误（结果不对）
给接下来要考级的你三句话：
一、看到一段代码问"输出什么"，就拿出草稿纸，一个变量一个变量地跟着走一遍。
二、写程序时先想清楚"顺序、分支、循环"用哪个，再动手敲键盘。
三、报错不要慌——先看行号，再看关键词，先从第一条错误改起。
二级我们会学更细的数据类型、多层分支与多层循环。路还长，但你已经上路了。
