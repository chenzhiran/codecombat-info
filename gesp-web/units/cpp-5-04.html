1　为什么需要链表

Why Linked Lists

1.1 数组的软肋

在数组中间插入一个数，有多麻烦 TEXT 
数组原本是：  10  20  30  40  50
              ↑0  ↑1  ↑2  ↑3  ↑4

想在 20 后面插入 25：

  ① 把 30、40、50 全部往后挪一格
         10  20  30  40  50  (空)
         10  20  (空) 30  40  50
  ② 再把 25 放进空出来的位置
         10  20  25  30  40  50

插一个数，动了一串数。
如果数组里有 100 万个数、要插在最前面——
那就要挪 100 万次。太慢了。
两个根本原因　 ① 数组的位置是固定的，插一个就得给别人腾地方；
② 因为位置固定，所以必须"把后面全部挪开"
打个比方： 数组就像电影院里编好号的一排座位——想在 3 号和 4 号之间塞进一个人， 4 号往后所有人都得挪一个位子。
如果座位是"按票号固定"的，那就必须挪；这排有一千个人，就得挪一千次。
而链表像"手拉手的队伍"——想插进去，只要松开两双手、重新牵上就行， 后面的人一个都不用动。

1.2 链表的想法：只记住下一节

链表的核心思想： 不用一个连续的数组，改用一堆"散落在各处的结点"， 每个结点里额外存一个"下一个结点在哪里"。
于是——
① 想插入？只要改两个结点里的"下一节是谁"，别人一根毛都不用动；
② 想删除？只要把前一个结点的"下一节"直接跳过后一个，也是两步的事；
③ 代价呢？想找第 10 个结点，只能从头一个一个数过去—— 因为谁也不知道第 10 个在内存的哪个角落。
这就是链表：用"找得慢"换来"改得快"。

2　结点与指针

Nodes & Pointers

2.1 结点长什么样

一个链表结点：数据 + 指向下一个的指针 C++ 
struct Node {
    int   value;        // ① 数据：这一节装的东西
    Node *next;         // ② 指针：下一节在哪儿（没有下一节就是 nullptr）
};

// 造一个新结点
Node *p = new Node();
p->value = 20;
p->next = nullptr;
结点只有两样东西　 ① 数据 value；② 指针 next——这就是"链"的全部秘密
注意 struct Node 里出现了 Node *next;。 这看起来像"自己包含自己"，但其实不是——
next 存的是另一个结点的地址， 而不是把那个结点整个塞进来。
所以它只占一个指针的大小（8 字节）——这个概念和上一单元学的指针完全一样。
顺便提醒：用 new 申请出来的结点，用完要 delete 掉。

2.2 头指针与尾指针

一个链表，靠两个指针"抓两头" C++ 
Node *head = nullptr;      // 头指针：指向第一节
Node *tail = nullptr;      // 尾指针：指向最后一节

// 空链表：head 和 tail 都是 nullptr

// 有个头指针，就能找到整条链
// 有个尾指针，就能 O(1) 在末尾接上新的一节

// 在表尾插入（已知 tail 时）
Node *s = new Node();
s->value = 99;
s->next = nullptr;
tail->next = s;            // 老末尾指向新结点
tail = s;                  // 尾指针挪到新结点
有了尾指针，尾插只要 2 步　 时间复杂度 O(1)
如果没有尾指针　得从头一路走到最后一节，那是 O(n)
为什么头指针是"命根子"？ 因为链表是散着放的——除了头指针，你不知道别的结点在哪。
一旦头指针丢了，整条链就"失联"了： 后面的结点还在内存里，可你再也找不到它们。
所以：① 别随手改 head；② 遍历时用另一个临时指针，别拿 head 去跑。

3　遍历与快慢指针

Traversal

3.1 一路走到底

遍历链表的标准写法 C++ 
// 写法一：用 while
Node *p = head;                 // ★ 从 head 开始，但不动 head
while (p != nullptr) {
    cout << p->value << " ";
    p = p->next;                // ★ 走到下一节
}

// 写法二：用 for（更紧凑）
for (Node *p = head; p != nullptr; p = p->next) {
    cout << p->value << " ";
}
要点　 ① 用临时指针 p，不要改 head 本身；
② 判断条件用 p != nullptr——走到最后一个结点的 next（空）就停
最容易崩的一个写法： while (p->next != nullptr) 会漏掉最后一个结点。 走完最后一个结点后 p 变成 nullptr， 下一轮判断 p->next 就是在访问空指针——程序直接崩溃。
正确做法：判断 p != nullptr， 在循环体里先取用 p->value、再 p = p->next。
顺序记牢：先看、再走。

3.2 快慢指针找中间

快指针走两步，慢指针走一步 C++ 
Node *middle(Node *head) {
    Node *slow = head;
    Node *fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;              // 慢的走一格
        fast = fast->next->next;        // ★ 快的走两格
    }
    return slow;                        // 慢的正好停在中间
}
横线上该填的就是　fast = fast->next->next;
原理　快的速度是慢的两倍——快指针走到头时，慢指针正好走了一半
为什么循环条件要写两个？ while (fast != nullptr && fast->next != nullptr)—— 两个都要判，缺一不可。
fast != nullptr：保证 fast->next 能安全访问 （否则就是在空指针上取成员，程序崩溃）。
fast->next != nullptr：保证 fast->next->next 能安全访问。
因为快指针一次要跳两格，所以必须"提前看一眼两格之后还在不在"。

4　插入与删除

Insert & Delete

4.1 在 p 之后插入

两步搞定，顺序不能反 C++ 
// 在结点 p 之后插入新结点 s
Node *s = new Node();
s->value = 25;

s->next = p->next;         // ① 新结点先接上后面的链
p->next = s;               // ② 再让 p 指向新结点

// 正确顺序：先接后，再改前
// 如果写反：
//   p->next = s;            // p 指向 s，原来的后继丢了
//   s->next = p->next;      // 这时 p->next 已经是 s 了 → s 指向自己！
OUTPUT　插入成功，时间复杂度 O(1)——
和链表的长度完全无关，只要知道 p 在哪儿就行
两句的顺序，是链表最经典的坑。 必须"先接后、再改前"： s->next = p->next; 再 p->next = s;
写反了会怎样？
① p->next = s; —— p 指向了新结点，可原来的后继"没人指向"了；
② s->next = p->next; —— 这时 p->next 已经等于 s， 于是 s->next = s——新结点指向了自己，后面的整条链全丢了。
记法：先用"老的 p->next"去接新结点的尾巴，最后才动 p->next。

4.2 删除结点

单链表：删 p 的后继 C++ 
// 删除 p 后面的那个结点
Node *q = p->next;          // ① 先记住要删的是谁
p->next = q->next;          // ② 让 p 跳过 q，直接连上 q 的后面
delete q;                   // ③ 释放 q 占的内存

// ★ 如果只写一句 p->next = p->next->next;
//   链是接对了，但那个结点再也找不到、也永远free不掉 —— 内存泄漏
三步　 ① 记住它；② 跳过它；③ 释放它
时间复杂度也是 O(1)
双向链表：删中间的结点 p C++ 
struct Node {
    int   value;
    Node *prev;             // 指向前一个
    Node *next;             // 指向后一个
};

// 删除 p（p 既不是头也不是尾）
p->prev->next = p->next;    // ① 前面的结点跳过 p，直接连 p 的后面
p->next->prev = p->prev;    // ② 后面的结点跳过 p，直接连 p 的前面
delete p;                   // ③ 释放 p
双向链表的好处　 有了 prev，删 p 时不用再从表头找它的前驱——两句就够

5　链表与数组的对比

Comparing

5.1 各自的长处

操作数组单链表
访问第 k 个元素O(1)——直接算地址O(n)——得从头数过去
在开头插入O(n)——后面全得挪O(1)——改一个指针
在已知结点后插入O(n)O(1)
删除已知结点的后继O(n)O(1)
在末尾追加O(1)（有长度记录时）O(1)（有尾指针时）
内存是否连续连续不连续，可以散放
能否随机访问能不能，只能顺序访问
空间开销只存数据每个结点多一个指针
一句话选结构： 经常"按下标取东西" → 用数组。
经常"在中间插进插出" → 用链表。
链表用"找得慢"换来了"改得快"；数组用"改得慢"换来了"找得快"。
没有哪个更好，只有哪个更合适——这就是学数据结构的意义。

5.2 双向链表

双向链表：两个方向都能走 C++ 
struct Node {
    int   value;
    Node *prev;         // 前驱
    Node *next;         // 后继
};

// 好处一：能倒着走
for (Node *p = tail; p != nullptr; p = p->prev) { ... }

// 好处二：删除自己不用找前驱
//         单链表删 p 得先从表头找到 p 的前一个，那是 O(n)
//         双向链表有 prev，直接就是 O(1)

// 代价：每个结点多存一个指针；插入删除时要多改一处

// 还有"循环链表"：让尾结点的 next 指回 head
//   tail->next = head;   → 走到末尾会自动回到开头
三种常见变体　 ① 单链表（只有 next）；
② 双向链表（有 prev 和 next）；
③ 循环链表（尾连回头，转圈走）
带哨兵结点的双向循环链表：四步操作不能随意调换顺序。 有时为了代码简洁，会在链表头尾各放一个"哨兵结点"—— 它们不存数据，只是为了让插入删除的逻辑统一。
但在这种链表里插入一个新结点，仍然要按固定顺序改指针： 先让新结点接上两边，再让两边接上新结点。
"四步操作无论什么顺序执行结果都正确"——这句话是错的。
顺序一旦颠倒，中间会出现"某边指不到"的瞬间，链就断了。

6　代码实战

Level Practice
关卡

无线电

进入关卡 →
故事：哨站里有一串机器人炮台，靠"下一个是谁"的链接首尾相连。
其中一个被等离子烧坏了，得把它换掉——可它在队伍正中间，前后都有人。
戈登说：先找到它前面那位，再改他们的"下一个"。

思路：链表只能顺着 next 一格一格走， 所以想换掉中间的一个，必须一边走一边记住"前一个"； 找到之后，让前一个指向备份、备份指向后面，链接就接上了。

重点示例：替换链表中间的一环 C++ 
Unit current = head;
while (current.next != nullptr) {          // 顺着 next 一格一格走
    if (current.next.id == brokenId) {     // 找到坏掉的那个的"前一个"
        backup.setNext(current.next.next); // ① 备份接管它的后继
        current.setNext(backup);           // ② 前一个指向备份
        break;
    }
    current = current.next;                // 继续往后走
}
要点　必须先接上后面、再改前面，否则链子就断了；setNext() 是关卡要求的写法
和本单元的关系： 这就是链表的看家本领：插入和删除只动两三个 next，不用像数组那样把后面的元素整体搬家。
代价是"不能直接跳到第 i 个"——只能从头顺着走。拿访问速度换修改速度，这就是链表。

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
链表这块，错法高度集中——就四类。前两条真题都考过。
1
删除结点时，先 delete 再用它。
扣哒鸭：Node *p = head; delete p; head = p->next; —— 这是典型错误：p 已经被释放了，再去读 p->next 就是在访问已释放的内存。
正确顺序是：先记下 head->next，再 delete。
正确写法：Node *q = head; head = head->next; delete q;
2
插入时两句顺序写反。
扣哒鸭：务必先 s->next = p->next;，再 p->next = s;。
写反的话，第二步会让新结点指向它自己——后面的整条链瞬间全部丢失。
记牢：先接后面，再改前面
3
遍历时拿 head 直接往前跑。
扣哒鸭：while (head != nullptr) head = head->next; —— 循环结束时 head 变成了 nullptr，整条链失去了唯一的入口。
结点还在内存里，可你再也没法找到它们了。
正确做法：用临时指针 for (Node *p = head; p != nullptr; p = p->next)
4
遍历条件写成 p->next != nullptr。
扣哒鸭：这个写法会漏掉最后一个结点——因为最后一节的 next 是空的。
更糟的是，如果拿它去取成员，走到空指针上就会直接崩溃。
判断条件统一写 p != nullptr。
正确写法：while (p != nullptr)

8　题目练习

Practice

前 5 题改编自 C++ 五级真题，其余为原创练习题。

改编自 2026 年 9 月 · C++ 五级 · 第 1 题单选题
小杨用单链表保存任务序列，并同时维护头指针 head 和尾指针 tail。在链表非空且已知 tail 的情况下， 在表尾插入新结点的时间复杂度是（　　）。
A.O(1)　　B.O(log n)　　C.O(n)　　D.O(n²)
查看答案与详解
答案：A。关键在于题目说了"已知 tail"。
既然尾指针就在手里，尾插只要两步：
tail->next = s; —— 让老末尾指向新结点；
tail = s; —— 尾指针挪到新结点上。
两步都是常数时间，和链表的长度一点关系都没有——所以是 O(1)。
那什么时候会变成 O(n)？ 如果没有尾指针，就只能从 head 一路走到最后一节——那才是 O(n)。
这道题考的就是"维护尾指针的价值"： 多存一个指针，就把尾插从 O(n) 降到了 O(1)。
对应小节2.2 头指针与尾指针。
改编自 2026 年 9 月 · C++ 五级 · 第 2 题单选题
在不带哨兵结点的双向链表中，结点 p 既不是头结点也不是尾结点。 删除 p 的正确代码是（　　）。
A.p->prev = p->next; p->next = p->prev; delete p;
B.p->prev->next = p; p->next->prev = p; delete p;
C.p->prev->next = p->next; p->next->prev = p->prev; delete p;
D.p->next = p->prev; p->prev->next = nullptr; delete p;
查看答案与详解
答案：C。删除 p 的本质是"让 p 的前后两个邻居直接牵手，把 p 摘出去"。
C 项做的正是这件事：
p->prev->next = p->next; —— 前驱的"下一个"直接跳过 p，指向 p 的后继；
p->next->prev = p->prev; —— 后继的"前一个"直接跳过 p，指回 p 的前驱；
delete p; —— 释放 p 占的内存。
A 项改的是 p 自己的两个指针—— 可 p 马上就要被删了，改它毫无意义，前后邻居根本没被接上。
B 项方向写反了：p->prev->next = p; 等于让前驱指向 p（本来就是），什么都没做。
D 项把 p 的后继指针倒着指，还顺手把前驱的 next 设成空—— 会把整条链从中间切断。
顺带说说双向链表的优势：有 prev，删 p 不用先从表头找它的前驱，直接 O(1) 搞定。
对应小节4.2 删除结点。

    return slow;
}
A.fast = fast->next;　　B.fast = fast->next->next;
C.fast = slow->next;　　D.fast = head->next;
查看答案与详解
答案：B。快慢指针的全部原理就是"速度差一倍"：
慢指针每次走 1 格，快指针每次走 2 格——快指针走到头时，慢指针正好走了一半。
所以横线处应该让快指针连挪两格：fast = fast->next->next; ✔
A 项让快指针也只走一格——两个指针速度一样，慢指针永远停在原地附近，根本找不到中点。
C 项fast = slow->next 是让快指针"跳到慢指针后面"， 和"快"没有任何关系，逻辑完全错乱。
D 项每次都把快指针重置到 head->next， 等于原地打转，永远出不了循环。
顺便注意循环条件为什么是两个： 因为快指针一次要跳两格，所以必须保证 fast 和 fast->next 都不是空——少判一个就会在空指针上取成员、直接崩溃。
对应小节3.2 快慢指针找中间。
改编自 2026 年 9 月 · C++ 五级 · 判断题 第 1 题判断题
下面代码在已知结点 p 的情况下， 能够以 O(1) 的时间在单链表的 p 结点之后插入新结点 s。（　　）
s->next = p->next;
p->next = s;
查看答案与详解
答案：正确（√）。这两句正是标准的"在 p 之后插入"写法，而且顺序是对的。
第一步 s->next = p->next; —— 新结点的"下一个"先接上 p 原来指向的那个结点（先把尾巴接好）；
第二步 p->next = s; —— 再让 p 指向新结点（把前面改好）。
顺序为什么不能反？先执行 p->next = s; 的话， 原后继的地址就丢了；接下来 s->next = p->next 取到的其实是 s 自己—— 新结点指向自己，后面的链全部失联。
时间复杂度为什么是 O(1)？ 整个操作只改了两次指针，和链表长度毫无关系——只要 p 已经在手里就行。
这正是链表相对数组的核心优势： 数组在中间插入要挪动后面所有元素（O(n)），而链表只要改两个指针（O(1)）。
对应小节4.1 在 p 之后插入。
改编自 2026 年 9 月 · C++ 五级 · 判断题 第 2 题判断题
下面代码可以安全地删除单链表的头结点，并使 head 指向删除后的新头结点。（　　）
Node *p = head;
delete p;
head = p->next;
查看答案与详解
答案：错误（×）。这两句的顺序整体反了，会造成"使用已释放的内存"。
问题出在第二句：delete p; 之后， p 指向的那块内存已经被归还给系统了； 接着写 head = p->next; 仍然在读取 p 的成员—— 这就是在访问一块已经不属于你的内存。
后果不可预测：那块内存可能已经被别的变量占用， 或者被系统标记为不可访问（程序直接崩溃）。
正确顺序应该是：先把 next 记下来，再释放。
Node *q = head;　→　head = head->next;　→　delete q;
一句话记牢："delete 之后，那个指针就再也不要去碰了。"
对应小节4.2 删除结点。
改编自 2026 年 6 月 · C++ 五级 · 判断题 第 1 题判断题
数组的存储空间在物理上通常是连续的，而链表的结点可以存储在不连续的内存空间中。（　　）
查看答案与详解
答案：正确（√）。这是数组与链表最根本的差别。
数组：一旦定义，就会在内存里申请一整块连续空间—— a[0]、a[1]……一个挨着一个。
正因为连续，才能靠"起始地址 + 下标 × 元素大小"直接算出任意元素的地址 （这就是数组能 O(1) 随机访问的原因）。
链表：每个结点都是单独 new 出来的， 系统给它们分配在哪里完全看当时哪块内存空着——彼此之间可以离得很远。
所以链表靠"每个结点里存着下一个结点的地址"来维持顺序—— 位置随意，但牵引关系明确。
由此衍生出两个结论：
① 数组能随机访问（O(1)），链表只能顺序访问（O(n)）；
② 数组插入删除要挪元素，链表只要改指针。
对应小节1.1 数组的软肋；5.1 各自的长处。
原创练习题单选题
一个长度为 n 的单链表（只有头指针 head， 没有尾指针），要在表尾插入一个结点，时间复杂度是（　　）。
A.O(1)　　B.O(log n)　　C.O(n)　　D.O(n²)
查看答案与详解
答案：C。注意题目说的是"没有尾指针"。
没有 tail 的情况下，你怎么知道最后一节在哪儿？ 只能从 head 开始一节一节数过去， 数到 next == nullptr 的那个才是末尾——这一步要走 n 次。
找到末尾之后再插入，是 O(1)；但"找"的过程是 O(n)，合起来就是 O(n)。
对比一下：如果维护了尾指针， 整个尾插只要 tail->next = s; tail = s; 两步——那就是 O(1)。
这正是"维护尾指针"的价值所在： 多花一个指针的空间，把尾插从 O(n) 降到 O(1)。
这也是做链表题时的第一直觉： "我需要经常在尾部操作吗？需要就顺手维护一个 tail。"
对应小节2.2 头指针与尾指针。
原创练习题判断题
在单链表中，只要知道结点 p 的位置， 就能以 O(1) 的时间删除 p 结点本身。（　　）
查看答案与详解
答案：错误（×）。这是一个非常容易想当然的陷阱。
删除 p 的动作是：让 p 的前驱直接指向 p 的后继。 所以你必须先找到 p 的前驱。
可单链表的指针是单向的—— 知道 p，却回不到它前面那个结点。 只能从表头一路找过去，那是 O(n)。
两种例外情况才能做到 O(1)：
① 题目给的是"p 的前驱"——那删 p 的后继就是 O(1)（前驱已知）；
② 用的是双向链表——结点里有 prev，直接就能找到前驱， p->prev->next = p->next; p->next->prev = p->prev; 两句搞定。
所以本题的说法在"单链表 + 只知道 p 本身"的前提下是错的。
对应小节5.2 双向链表。
原创练习题编程题
题目要求：读入 n 个整数，用单链表把它们存起来， 然后把链表反转（就地反转，不新建链表），最后按反转后的顺序输出。
样例：输入 5 / 10 20 30 40 50， 输出 50 40 30 20 10。
查看参考答案与要点 
#include <iostream>
using namespace std;

struct Node {
    int   value;
    Node *next;
};

int main() {
    Node *head = nullptr, *tail = nullptr;
    int n;
    cin >> n;

    for (int i = 1; i <= n; i++) {           // 建链
        int x;  cin >> x;
        Node *s = new Node();
        s->value = x;
        s->next = nullptr;
        if (!head) head = tail = s;
        else { tail->next = s; tail = s; }
    }

    // ★ 就地反转：三个指针一路往后推
    Node *prev = nullptr, *cur = head;
    while (cur != nullptr) {
        Node *nxt = cur->next;    // ① 先记住下一个
        cur->next = prev;         // ② 让当前结点掉头
        prev = cur;               // ③ prev 跟上来
        cur = nxt;                // ④ cur 继续往前
    }
    head = prev;                  // ★ 反转后 prev 就是新的表头

    for (Node *p = head; p != nullptr; p = p->next) {
        cout << p->value << " ";
    }
    cout << endl;

    while (head) { Node *q = head; head = head->next; delete q; }
    return 0;
}

输入 5 / 10 20 30 40 50 输出：50 40 30 20 10
要点：
① 就地反转需要三个指针：prev、cur、nxt ——因为一旦把 cur->next 改成指向前方，后面的链就断了，所以必须先用 nxt 记住。；
② 四步的顺序不能乱：先记 nxt、再掉头、再推 prev、最后推 cur；
③ 循环结束后一定要写 head = prev;—— 此时 cur 已经是 nullptr， 原来的表头变成了表尾，而 prev 才是新表头。；
④ 整个过程只改了指针方向，没有申请新结点——这就是"就地"的含义， 空间复杂度 O(1)；
⑤ 释放内存那段仍然要"先记、后挪、再删"。
对应小节4.1 在 p 之后插入；6 代码实战。

9　本单元小结

Unit Summary
塞尼克 · 沙海向导
四句话记住链表：
一、数组连着放、靠下标找；链表散着放、靠指针牵。
二、结点 = 数据 + 指向下一个的指针；头指针丢了，整条链就失联。
三、插入"先接后、再改前"；删除"先记住、再跳过、最后 delete"。
四、链表用"找得慢"换"改得快"——O(n) 找、O(1) 改，正好和数组相反。
队伍拉起来了。下一站是折半寻宝——那里要在一整排宝格里，用"砍一半"的办法把答案逼出来。

你在商队旁收获了什么

  • 数组的软肋——位置固定，中间插入删除要挪动后面所有元素（O(n)）。
  • 链表的思想——不用连续空间，每个结点记住"下一个在哪儿"。
  • 结点结构——struct Node { int value; Node *next; };， 数据 + 指针，仅此两样。
  • 头指针——整条链唯一的入口，丢了就全失联；遍历要用临时指针。
  • 尾指针——有了它，尾插从 O(n) 降到 O(1)。
  • 遍历写法——for (Node *p = head; p != nullptr; p = p->next)， 判断用 p != nullptr。
  • 快慢指针——快的走两格、慢的走一格，一趟找到中点。
  • 插入两步——s->next = p->next; 再 p->next = s;， 顺序不能反，复杂度 O(1)。
  • 删除三步——记住它、跳过它、delete 它； 绝不能 delete 之后再去读它。
  • 双向链表——多了 prev，删自己不用找前驱，代价是多存一个指针。
  • 循环链表——tail->next = head;，走到末尾自动回到开头。
  • 核心取舍——数组：找得快、改得慢；链表：改得快、找得慢。
