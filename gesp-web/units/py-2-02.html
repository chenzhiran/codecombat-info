1　算法：做事的步骤

What Is an Algorithm

先来玩个小游戏。假设你是岗哨的新兵，队长让你"去把火把点上"。 你会怎么做？

你大概会说：先走到火把前，再掏出火折子，然后吹一口气，最后把火折子凑近灯芯。 ——这四步，就是一套算法。

算法的定义： 为解决一个问题而采取的一步一步的方法和步骤，就叫算法。
它有三个关键要求：① 每一步都清楚；② 有确定的顺序；③ 做完一定会结束。

你可能会想：算法这个词听起来好高级。但你其实每天都在用它——

生活场景算法的步骤
泡一碗面烧水 → 撕开包装 → 放调料 → 倒水 → 等三分钟 → 吃
早上出门上学起床 → 刷牙洗脸 → 吃早饭 → 背书包 → 出门
英雄去取宝石向右走 → 向下走 → 捡起宝石 → 走回来
判断能不能出门看天气 → 下雨就带伞 → 不下雨就不带 → 出门
艾达 · 冰霜法师
我煮药水最讲究顺序。
先放冰晶再点火，药水是清的；先点火再放冰晶——"砰"，眉毛就没了。
你看，同一批材料、同样的动作，顺序一换，结果完全不一样。这就是算法里"顺序"的分量。

2　三种描述方式

Three Ways to Describe It

问题来了：算法在脑子里是一回事，要说给别人听又是另一回事。 人们发明了三种描述方式，各有各的用处。

2.1 自然语言

就是我们平时说的、写的语言。优点是谁都能看懂； 缺点是啰嗦，而且容易产生歧义。

歧义的经典例子： 你写了一句"把门口的人叫过来"。
于是新兵去叫了——结果把整支巡逻队都叫来了。 "门口的人"是一个还是十个？自然语言说不清楚，计算机更不可能猜。

2.2 流程图

用图形符号 + 箭头把步骤画出来。它最大的好处是一眼就能看到"往哪儿走"， 分支和循环看得清清楚楚。

2.3 伪代码

伪代码（Pseudo-code）是一种"像代码、但又不受任何语言语法约束"的写法。 你可以写 如果 火没着：再吹一次——它不是 Python，也不是别的语言， 但任何人都能一眼看懂逻辑，而且翻译成真正的代码非常容易。

三句话记住三种方式：
自然语言——给人随口说，方便但啰嗦；
流程图——给人看全局，直观但画起来费事；
伪代码——给程序员打草稿，接近代码但自由。

3　流程图的四种符号

Flowchart Symbols

流程图有一整套"标准零件"。考试只考四个，背下来就行：

符号形状代表什么例子
起止框圆角矩形流程开始或结束开始 / 结束
处理框矩形执行一步操作或计算total = a + b
判断框菱形判断条件，分两条路（是 / 否）a > b ？
输入输出框平行四边形输入数据或输出结果输入 n ／ 输出 total
流程线带箭头的线表示执行的方向↓
扣哒鸭 · 调试官
我见过太多人把菱形当成"装饰"。
记住一条就够：菱形是最危险的形状——它会分叉。 看到菱形，你就知道接下来有两条路，一定要看清哪条是"是"、哪条是"否"。

4　三种结构的画法

Three Structures in Flowcharts

一级学过三种基本结构，现在我们把它们"画出来"。

看流程图的三个看点：
① 有几条路——全是直下就是顺序；出现菱形分叉就是分支；
② 有没有往回走的箭头——有虚线/箭头指回上方，就是循环；
③ 出口在哪——顺着箭头一路走到底，看看最后落到哪个框。

5　编程语言的层次

Levels of Programming Languages

一级里我们已经见过这张表，二级要再补一个关键区别：编译 vs 解释。

层次由什么组成计算机能直接执行吗需要什么
机器语言二进制指令（0 和 1）能，直接执行不需要翻译
汇编语言助记符号（如 MOV、ADD）不能汇编器
高级语言接近自然语言的语句不能编译或解释
一句话区分： 编译是"整本书一次翻完再读"，解释是"一句一句现场翻译"。
Python 属于解释型语言，所以它写完就能立刻运行——这也是它最适合初学者的原因。

6　代码实战

Level Practice
关卡

蜿蜒小径

进入关卡 →
故事：溪谷北边有一条被灌木遮住的小径，弯弯绕绕穿过森林。 你手里拿着地图，可地图上只有几个孤零零的标记点——你得自己规划出一条路来。
而且走到小径尽头时，还得顺手在那儿修一道栅栏，把追来的食人魔挡在外面。

思路：看上面的关卡实况——小径弯弯绕绕，地图上只有几个孤零零的标记点。 这一关你换上了新装备 moveXY(x, y)：它不像"向右走三步"那么笨， 而是让你直接说出目的地坐标，它会自动帮你找路。
先把路线想清楚（这就是"算法"），再一行一行写下来。

重点示例：按坐标一步一停 Python 
hero.moveXY(36, 59)    # 走到上游的第一个标记点
hero.moveXY(37, 12)    # 再折向下方
要点　一步一个坐标，顺序不能乱；后面还有两段路，写法完全一样
画成流程图会是这样： 开始 → 移动到 (36,59) → 移动到 (37,12) → 移动到 (66,17) → 在 (71,24) 建造栅栏 → 结束。
四条"处理框"加两个"起止框"，一条直线走到底——这就是最典型的顺序结构流程图。
先想清楚再动手：如果一上来就乱写坐标，英雄会撞进灌木丛。 试着先在纸上把路线画出来——这就是流程图存在的意义。

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
流程图这章，错误全在"看图不仔细"。四条，条条都是阅卷老师最爱设的坑。
1
菱形只走了一条边。看到判断框，只顺着"是"往下读，把"否"那条路忘了。
扣哒鸭：菱形一定有两条出路。 只读一条，就像只看地图的一半然后出门——迷路是必然的。
正确做法：看到菱形，先分别标出"是"走哪、"否"走哪，再往下算
2
把循环的回线看漏了。以为流程一路向下，其实虚线箭头又绕回了上面。
扣哒鸭：流程图里"往回指"的箭头，就是循环的标志。 看到它，你就要在心里数：这一圈跑了几次？跑了几圈才出去？
正确做法：先找有没有指回上方的箭头，有就是循环
3
把平行四边形当成处理框。看到"输入 n"以为是"计算 n"。
扣哒鸭：平行四边形是输入输出专用——它的活儿是"跟外界打交道"， 不是"算数"。看到它就知道：这里要么在读数据，要么在写结果。
正确做法：平行四边形 → input / print；矩形 → 赋值与计算
4
以为 Python 需要先编译才能运行。
扣哒鸭：Python 是解释型语言，写完直接运行，不用先编译成 exe。 这就是为什么你改一行代码，马上就能看到结果。C++ 才需要先编译。
正确理解：编译型（C/C++）vs 解释型（Python）

在流程图中，表示"判断"的符号是（　　）。
A.圆角矩形　　B.矩形　　C.菱形　　D.平行四边形
查看答案与详解
答案：C。
圆角矩形表示起止，矩形表示处理（执行一步操作），菱形表示判断， 平行四边形表示输入输出。

原创练习题单选题
下列关于算法的说法，错误的是（　　）。
A.算法是解决某个问题的方法和步骤
B.算法可以用自然语言、流程图或伪代码来描述
C.一个算法可以没有结束，一直执行下去
D.算法的每一步都应该是明确的、没有歧义的
查看答案与详解
答案：C。算法必须满足有限性——执行有限个步骤之后一定要结束。 "永远执行下去"的程序虽然存在（比如死循环），但它不能算一个合格的算法。
对应小节1 算法：做事的步骤。
原创练习题单选题
下面这段伪代码描述的是哪种基本结构？（　　）
输入 n
如果 n > 0：
    输出 "正数"
否则：
    输出 "非正数"
A.顺序结构　　B.分支结构　　C.循环结构　　D.无法判断
查看答案与详解
答案：B。出现了"如果……否则……"，也就是根据条件选择不同分支， 属于分支（选择）结构。
顺序结构没有条件判断；循环结构会出现"重复执行"或"直到"之类的字样。
对应小节4 三种结构的画法。

原创练习题单选题
用一个流程图描述"求 1 到 100 的和"，图中一定不会出现哪种符号？（　　）
A.起止框（圆角矩形）
B.处理框（矩形）
C.判断框（菱形）
D.连接网络的符号
查看答案与详解
答案：D。求 1 到 100 的和需要：起止框（开始、结束）、 处理框（累加、计数器 +1）、判断框（是否到 100），以及输入输出框（输出结果）。
"连接网络"根本不是流程图的基本符号，属于干扰项。
对应小节3 流程图的四种符号；4 三种结构的画法。
原创练习题编程题
题目要求：已知算法步骤为—— ① 输入两个数 a、b；② 计算 a + b；③ 输出结果。 请用 Python 把这三步写出来，并在每行加上注释说明它对应流程图中的哪一步。
查看参考答案与要点 
# ① 输入：对应流程图中的"平行四边形"
a = int(input("请输入第一个数："))
b = int(input("请输入第二个数："))

# ② 处理：对应流程图中的"矩形"
total = a + b

# ③ 输出：对应流程图中的"平行四边形"
print(total)

要点：
① 输入要用 int() 转成整数；
② 计算结果先存进变量，对应"处理框"；
③ 输出用 print()，与输入同属平行四边形；
④ 整段程序就是最典型的顺序结构。
对应小节4 三种结构的画法。

9　本单元小结

Unit Summary
贺舒曼 · 镜中先知
三句话收尾。
第一，算法就是"做事的步骤"，必须有明确顺序、有终点、不能有歧义。
第二，流程图有四个零件：圆角起止、矩形处理、菱形判断、平行四边形输入输出。
第三，Python 是解释型语言，写完就能跑。
还有一句送给你们——高手写代码之前，都会先在纸上画一画。

你在羊皮纸上学到了什么

  • 算法——解决问题的一步步方法，要求明确、有序、能结束。
  • 三种描述方式——自然语言（随口说）、流程图（画出来）、伪代码（像代码的草稿）。
  • 流程图四符号——圆角=起止，矩形=处理，菱形=判断，平行四边形=输入输出。
  • 三种结构——顺序是一条道走到底；分支由菱形分叉；循环有指回上方的箭头。
  • 语言层次——机器语言 → 汇编语言 → 高级语言。
  • 编译与解释——C/C++ 先编译再运行；Python 边解释边运行，改完立刻见效。
