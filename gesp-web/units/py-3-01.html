1　负数为什么难存

Why Negatives Are Tricky

1.1 先约定：八位二进制

先把基础打牢。我们约定：下面所有例子都用 8 位二进制（正好一个字节）。

1.2 正数很好办

正数很好办。5 写成八位二进制就是 0000 0101——从右往左，每一位代表 1、2、4、8、16……

1.3 负数的两个麻烦

打个比方： 八位二进制就像一排八个只有"开"和"关"两种状态的灯——没有"半开"，也没有"红色"。
既然灯只能表示 0 和 1，那"负号"这个东西就根本没地方放。
所以人们只能"挪用"一个灯位，专门拿来当正负号的标记——这就是符号位的由来。

可负数怎么办？八个格子里只有 0 和 1，没有"-"这个符号。

全世界的解决办法： 拿出最左边那一位当"符号位"——
0 表示正数，1 表示负数。
剩下七位才是真正的数值。

所以八位二进制被分成了两半：

区段位权作用
第 8 位（最左边）符号位0 = 正，1 = 负
第 1~7 位数值位真正的数字大小
凌克 · 影瞳刺客
我们刺客的暗号也有个规矩：最前面那一声轻敲，不代表数量，只代表"是好消息还是坏消息"。
后面敲几下才是在报数。
八个格子里，最左边那位干的就是这件事——它不参与计数，只管表态。

2　原码：最直观的写法

Original Code

2.1 符号位：借一格当正负号

有了符号位，第一套方案立刻就能想出来：正数照写，负数就把符号位改成 1，数值位原样不动。 这就是原码。

原码举例（8 位） 定点数 
+5  →  0 000 0101        +12  →  0 000 1100
-5  →  1 000 0101        -12  →  1 000 1100

+0  →  0 000 0000        -0   →  1 000 0000   ← 两个零！
读法　第一位看正负，后七位看大小

2.2 原码的两个麻烦

打个比方： 用原码做加减法，就像家门口挂着四把不同的钥匙——正加正、正加负、负加正、负加负，
每种情况都得先认出"我是哪一类"，再去掏对应的那把钥匙。
机器做起来又慢又容易出错。人们希望的是：不管正负，都用同一套动作就能算出来。

原码很好懂，可它有两个大麻烦：

麻烦一：0 有两种写法。 +0 和 -0 明明是同一个数，机器里却存成两种样子。 判断"这个数是不是 0"要检查两遍，白白浪费了一个编码。
麻烦二：加减法要分四种情况。 同号相加、异号相减、还要比较谁大谁小…… 硬件电路得做得特别复杂。越复杂，越慢、越容易出错。

3　反码：给负数翻个面

One's Complement

3.1 反码的规则

人们想：既然负数不好算，那能不能让负数"长得"'更像'正数一点？ 于是反码来了。规则简单到一句话：

反码规则： 正数的反码 = 它的原码（不用改）。
负数的反码 = 符号位不变，其余各位全部取反（0 变 1，1 变 0）。
反码举例（8 位） 定点数 
+5  →  0 000 0101        正数：反码 = 原码，原样照抄

-5  →  1 000 0101        先写出原码
    →  1 111 1010        符号位不动，后七位全部取反

0   →  0 000 0000（+0） / 1 111 1111（-0）   ← 还是两个零
口诀　正数照抄，负数"符号不动，其余全翻"
贺舒曼 · 镜中先知
照镜子的时候，镜子里的你左右是反的，但站位没变。
反码就是这个思路：符号位站着不动，后面七位进镜子翻个面。
可惜光翻面还不够——镜子里的"零"，和外面的"零"，毕竟是两个影子。

3.2 反码解决了什么，又留下了什么

4　补码：计算机真正用的

Two's Complement

4.1 补码：反码再加 1

打个比方： 补码很像钟表上的指针——表盘只有十二个刻度，
往前拨 3 格和往后拨 9 格，最后停在同一个位置。
既然表盘是"转圈"的，那"减去一个数"就可以改写成"加上另一个数"，而且结果一模一样。
这正是补码能把减法变成加法的原因。

最后一招来了，而且赢得干净利落：在反码的基础上再加 1。

补码规则（重中之重）： 正数的补码 = 它的原码（不变）。
负数的补码 = 反码 + 1（也就是：原码 → 符号位不动、其余取反 → 再加 1）。
补码举例（8 位） 定点数 
+5  →  0 000 0101        正数：补码 = 原码

-5  原码 1 000 0101
    反码 1 111 1010
    补码 1 111 1011      ← 反码加 1

0   →  0 000 0000        只有这一种写法，干净利落
口诀　正数照抄；负数"取反加一"

4.2 为什么说"减法变加法"

算 5 - 3。用补码，我们可以把它当成 5 + (-3) 来做：

5 + (-3) 的补码运算 定点数 
  5 的补码    0000 0101
+-3 的补码    1111 1101        (-3 的补码：取反加一)
─────────────
  相加得      1 0000 0010
  丢掉最高位  0000 0010   →  2   ✔ 正确！
要点　最左边多出来的那一位，硬件自动丢掉——这叫"按位截断"
扣哒鸭 · 调试官
这一步最容易看傻眼：加起来怎么多出一位？
别慌。八位机器只认八位，第九位自动溢出丢弃，就像算盘上珠子里多出来的那一颗， 根本不在格子里。
结果是 0000 0010，也就是 2——5 减 3 确实是 2。完美。

5　三码速查与互换

Quick Reference

5.1 三码速查表

真值原码反码补码
+50 000 01010 000 01010 000 0101
+10 000 00010 000 00010 000 0001
-11 000 00011 111 11101 111 1111
-51 000 01011 111 10101 111 1011
-121 000 11001 111 00111 111 0100
00 000 0000 / 1 000 00000 000 0000 / 1 111 11110 000 0000
规律发现： 正数的原码 = 反码 = 补码，永远一模一样。
只有负数才需要"取反""加一"。
小技巧：-1 的补码是 1111 1111（八个 1 全亮）， 这是个特别好记的特殊值。

反过来：给补码，怎么求真值？

5.2 从补码倒推原数

考试也常倒着考：给你 1111 0110，问它是多少。方法有两条——

由补码求真值（以 1111 0110 为例） 两种思路 
方法一：还原回去算
  1111 0110            最高位是 1 → 一定是负数
  取反 → 1000 1001
  加一 → 1000 1010     得到原码，数值位 000 1010 = 10
  所以真值是 -10

方法二：按"位权"直接算
  最高位权  -128
  1×(-128) + 1×64 + 1×32 + 1×16 + 0×8 + 1×4 + 1×2 + 0×1
  = -128 + 64 + 32 + 16 + 4 + 2 = -10   ✔ 两种方法结果一致
要点　方法一适合手算，方法二能帮你校验
方法二为什么用 -128？ 因为在补码里，最高位的权值从 +128 变成了 -128——这正是补码最巧妙的地方： 它把"符号位"和"数值位"统一到一套加法规则里去了。

6　范围与溢出

Range & Overflow

6.1 八位补码的范围

打个比方： 八位二进制一共能排出 2 的 8 次方 = 256 种不同的组合。
补码把这 256 种组合平均分成两半：一半表示 0 和正数，一半表示负数。
可"零"只有一个，却占掉了正数那边的第一格，于是多出来的那一格就分给了负数—— 所以范围是 −128 ~ 127，负数比正数多一个。

6.2 溢出是怎么回事

八位补码能表示多少个数？算一算：一共 2^8 = 256 种组合， 其中一半是负数、一半是非负数。

必记结论： n 位补码能表示的整数范围是 -2n-1 ～ 2n-1 - 1。
8 位：-128 ~ 127；16 位：-32768 ~ 32767。
负数比正数多一个，这是补码的特点（因为 0 算在正数那边）。

那什么叫溢出？很简单：算出来的结果超出了能表示的范围。

溢出的例子 定点数 
127 + 1 = ?
  127 的补码   0111 1111
+ 1           0000 0001
──────────────
              1000 0000   →  按补码解释是 -128   ✘ 明显错了

-128 - 1 = ?
  -128         1000 0000
+ -1           1111 1111
──────────────
              0111 1111   →  变成了 +127        ✘ 也错了
要点　两个正数相加却得到负数，或两个负数相加却得到正数——这就是溢出的信号
做题小窍门： 先按正常数学把结果算出来，再看看它是不是落在 -128 ~ 127 里。落在外面，就是溢出。 考试里这种题基本上都是送分题，别被那一长串二进制吓到。

7　代码实战

Level Practice
贺舒曼 · 镜中先知
我知道你在想什么：原码补码这么绕，跟写代码有什么关系？
关系可大了。补码解决的核心问题是"怎么用简单的规则处理复杂的情况"， 而这个思路，在写程序时天天都用得上。
下面这一关，就是同一个思路的另一种模样。
关卡

非与或

进入关卡 →
故事：矿坑的岔路口堆着杂七杂八的东西——有的能捡，有的碰不得； 远处的食人魔也不全该打，有个叫 burl 的家伙其实是友军。
你得给程序定一套规矩：什么样的东西该收，什么样的敌人该打。 规矩定得越准，动作就越省。

思路：用 or 表示"满足其中之一就行"， 用 and 表示"两个条件都要成立"， 用 != 表示"不是这个"。

它们和位运算里的"或、与、非"是同一family——只不过一个作用于真假，一个作用于每一位。

重点示例：把"规矩"写成条件 Python 
# 只捡 potion 或 lightstone 这两种东西
if item.type == "potion" or item.type == "lightstone":
    hero.moveXY(item.pos.x, item.pos.y)

# 攻击条件：不是 burl，并且距离小于 15
if enemy.type != "burl" and distance < 15:
    hero.attack(enemy)
要点　or 松、and 严、!= 排除；剩下的框架留给你自己搭
和本单元的关系： 位运算里的"与、或、异或、取反"，处理的是每一位的 0/1； 而这里的 and / or / not，处理的是整个条件的真假。
内核是同一个：把复杂判断拆成几条简单规则，再组合起来。

8　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
三码互化这章，错法高度集中。下面四条，我给学生讲过不下几百遍。
1
给负数取反时，把符号位也翻了。结果正负号都变了。
扣哒鸭：符号位是"身份牌"，不能动。 取反只对后面七位动手——记住这句：翻身子，不翻脸。
正确做法：符号位保持 1，只把数值位取反
2
把"反码加一"加到了符号位上。八个位一起加，越加越乱。
扣哒鸭：加一加在最低位上，一位一位往前进位。 正常情况它根本进不到最左边那个符号位——除非你算错了。
正确做法：反码的最低位 +1，按二进制进位规则往左推
3
以为 -128 的补码是 1 000 0000 的"原码直接读"。 又或者以为范围是 -127 ~ 127。
扣哒鸭：1000 0000 在补码里表示 -128，它是个特例—— 没有对应的原码和反码（因为 -128 超出了 7 位数值位能表示的范围）。
范围记牢：八位是 -128 ~ 127，不是对称的。
正确记法：-2n-1 ~ 2n-1-1；8 位即 -128 ~ 127
4
把原码的三位一组当成了"位权"。写 000 0101 时不知道它读作 5。
扣哒鸭：后面的七位就是二进制数，按 4、2、1 的位权加起来。 000 0101 = 4 + 1 = 5。 实在拿不准就拆成 8-4-2-1 四组来读。
正确读法：数值位的位权从右往左是 1、2、4、8、16、32、64

9　题目练习

Practice

第 1 题改编自 2026 年 9 月 · Python 三级 第 3 题，其余为原创练习题。

改编自 2026 年 9 月 · Python 三级 · 第 3 题单选题
符文矿坑的记账石板上刻着 8 位二进制原码。
这 8 位原码能表示的最小整数和最大整数分别是（　　）。
A.−128、128
B.−128、127
C.−127、128
D.−127、127
查看答案与详解
答案：D。原码用最高位当符号位（0 正 1 负），剩下 7 位表示数值大小。
正数最大：0111 1111 = 127；
负数绝对值最大：1111 1111 = −127。
为什么不是 −128？因为 8 位原码里 1000 0000 表示的是"负零"，它和"正零"重复了 —— 原码的零有两种写法，这也是它不方便直接做加减法的原因。
对比一下：补码同样 8 位能表示 −128 ~ 127，比原码多出一个 −128，而且零只有一种写法。
对应小节2 原码：最直观的写法。
原创练习题单选题
十进制数 -6 的 8 位二进制补码是（　　）。
A.1 000 0110　　B.1 111 1001　　C.1 111 1010　　D.1 111 1011
查看答案与详解
答案：C。三步走：
① 原码：符号位取 1，数值位 6 = 000 0110 → 1 000 0110；
② 反码：符号位不动，后七位取反 → 1 111 1001；
③ 补码：反码最低位加 1 → 1 111 1010。
易错点：A 是原码，B 是反码，D 是 -5 的补码。
对应小节4 补码：计算机真正用的。
原创练习题单选题
已知某数的 8 位补码为 1111 1101，它的十进制真值是（　　）。
A.-3　　B.-2　　C.253　　D.-125
查看答案与详解
答案：A。两种算法都可以：
方法一：取反得 1000 0010，加一得 1000 0011（原码）， 数值位 000 0011 = 3，所以真值是 -3。
方法二：按位权算，最高位是 -128： -128 + 64 + 32 + 16 + 8 + 4 + 0 + 1 = -3。
提示：-1 的补码是 1111 1111， -3 就是它减 2，即 1111 1101——熟手可以秒答。
对应小节5 三码速查与互换。
原创练习题判断题
在补码表示中，数字 0 只有一种写法，即 0000 0000。（　　）
查看答案与详解
答案：正确（√）。这正是补码优于原码、反码的关键之处——原码和反码里的 0 都有两种写法（正零、负零），补码把这个问题消灭了。
省下来的编码 1000 0000 就分给了 -128。
对应小节4 补码；6 范围与溢出。
原创练习题单选题
8 位补码能表示的十进制整数范围是（　　）。
A.-127 ~ 127　　B.-128 ~ 127　　C.-128 ~ 128　　D.0 ~ 255
查看答案与详解
答案：B。公式：-2n-1 ~ 2n-1-1， n = 8 时即 -128 ~ 127。
一共 256 个数：负数 128 个、非负数 128 个。
A 是原码/反码的范围（因为零占了两个编码）；D 是 8 位无符号数的范围。
对应小节6 范围与溢出。
原创练习题判断题
在 8 位补码运算中，127 + 1 的结果是 128。（　　）
查看答案与详解
答案：错误（×）。8 位补码最大只能表示 127， 0111 1111 + 0000 0001 = 1000 0000， 而 1000 0000 按补码解释是 -128。
这是典型的"正溢出"：两个正数相加得到负数。
对应小节6 范围与溢出。
原创练习题单选题
十进制数 -1 的 8 位反码与补码分别是（　　）。
A.1 111 1110 与 1 111 1111
B.1 000 0001 与 1 111 1110
C.1 111 1111 与 1 111 1111
D.1 000 0001 与 1 111 1111
查看答案与详解
答案：A。① 原码 1 000 0001； ② 反码 = 后七位取反 → 1 111 1110； ③ 补码 = 反码加 1 → 1 111 1111。
记牢：-1 的补码是八个 1 全亮，这是最常考的特殊值。
对应小节5 三码速查与互换。
原创练习题编程题
题目要求：编写程序，对输入的十进制整数 n（-128 ≤ n ≤ 127）， 求它的 8 位二进制补码并以字符串形式输出（不足 8 位时左边补 0）。
查看参考答案与要点 
n = int(input("请输入一个整数（-128~127）："))

# Python 里负数内部就是用补码存的，
# n & 0xFF 可以把 -1 变成 255（也就是 1111 1111）
value = n & 0xFF

# 二进制字符串，前面补 0 到 8 位
bits = bin(value)[2:].zfill(8)

print(bits)

运行示例：输入 -5 → 输出 11111011
要点：
① 在 Python 里，整数本来就是用补码存在的，负数直接转二进制会得到 -101 这种带负号的形式；
② n & 0xFF 是"按位与"，取低 8 位的效果 —— 这正是下一单元位运算的内容；
③ bin() 把数字转成二进制字符串（带 0b 前缀）， zfill(8) 负责左边补零。
对应小节4 补码；预告下一单元的位运算。

Unit Summary
贺舒曼 · 镜中先知
收成三句话，你就能走遍这一章：
一、正数的原码、反码、补码一模一样，只有负数才要"取反加一"。
二、补码赢在两点：零只有一种写法；减法能当加法算。
三、8 位补码的范围是 -128 ~ 127，负数比正数多一个。
记住这三条，剩下的都是练习题。

你在暗河边上收获了什么

  • 机器数与真值——机器里真存的 0/1 是机器数，它代表的数字是真值。
  • 符号位——最高位约定：0 正、1 负；剩下七位才是数值。
  • 原码——符号位 + 数值位；缺点：零有两种写法，加减要分情况。
  • 反码——负数"符号位不动，其余全翻"；缺点：零还是两种写法。
  • 补码——负数"取反加一"；零唯一，减法变加法，计算机实际采用。
  • 由补码求真值——可以"取反加一还原成原码"，也可以按最高位权重 -2n-1 直接算。
  • 范围与溢出——n 位补码范围 -2n-1 ~ 2n-1-1；8 位为 -128 ~ 127。
