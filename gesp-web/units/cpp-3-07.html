1　枚举法

Enumeration

1.1 枚举法是什么

枚举法的思路简单到一句话：把所有可能的情况一个一个拿出来检验，找到符合条件的那一个。

枚举的骨架就三层 C++ 
for (每一个可能的情况) {
    if (这个情况符合题目条件) {
        输出 / 记录它
    }
}
就这么简单　一个循环走遍所有可能，里面一句判断筛出答案
打个比方： 枚举法就像一串钥匙挨个去试锁——不猜、不推理，一个一个试过去，总有一把能开。
看着笨，可它有个大优点：只要范围列全了，就一定不会漏掉答案。
而且"挨个试"这件事，计算机做得又快又不会烦——人试一百次就晕了，它试一百万次也面不改色。

1.2 什么时候该想到它

三个信号，出现一个就该考虑枚举： ① 答案的范围很小、很明确——比如"三位数"、"1 到 1000 之间"。
② 没什么好办法能"猜"出答案——想不出公式，那就试。
③ 需要"找出所有满足条件的解"——这一步枚举最擅长。
反过来说：如果范围大到几亿，那枚举就跑不完了，得换别的办法。

2　不重不漏

No Missing, No Repeat

2.1 不重不漏

枚举法只有一条铁律，但它是所有错误的总源头：

铁律：不重不漏。 不漏——每个可能的情况都要被试到，漏一个就可能错过正确答案。
不重——同一个情况不要试两遍，重复会让结果多算。
这两条听起来像废话，可 90% 的枚举题错就错在这里。
打个比方： 枚举要像清点仓库里的箱子——每一箱都要点到，一箱都不能漏；也不要来回重复点同一箱。
所以动手前先想清楚三件事：从哪里开始、到哪里结束、每次跨多少。

2.2 起点、终点与步长

题目要求怎么写循环说明
1 到 100 的所有整数for (int i = 1; i <= 100; i++)两端都取到
所有的三位数for (int i = 100; i <= 999; i++)不是从 0 开始
1 到 100 的偶数for (int i = 2; i <= 100; i += 2)用步长直接跳过奇数
1 到 100 的奇数for (int i = 1; i <= 100; i += 2)起点是 1
n 个数的数组for (int i = 0; i < n; i++)下标从 0 开始
最常错的三个地方： ① 端点写错——该写 <= 的地方写了 <，结果正好漏掉最后一个。
② 起点写错——"三位数"从 100 开始，别从 0 或 1 开始。
③ 忘了处理"相等"——题目说"不超过 n"，那就要用 <=。
破解办法：拿一个最小的例子代进去，看看边界那一项有没有被算到。

3　枚举的经典例题

Classic Examples

3.1 水仙花数

所谓水仙花数，就是一个三位数，它各位数字的立方和恰好等于它自己。
比如 153：1³ + 5³ + 3³ = 1 + 125 + 27 = 153 —— 正好等于它本身。

枚举所有三位数，一个个验算 C++ 
#include <iostream>
using namespace std;

int main() {
    for (int i = 100; i <= 999; i++) {      // 枚举所有三位数
        int a = i / 100;                     // 百位
        int b = i / 10 % 10;                 // 十位
        int c = i % 10;                      // 个位

        if (a*a*a + b*b*b + c*c*c == i) {
            cout << i << " ";
        }
    }
    cout << endl;
    return 0;
}
OUTPUT　153 370 371 407
验算 370　3³ + 7³ + 0³ = 27 + 343 + 0 = 370 ✔
验算 407　4³ + 0³ + 7³ = 64 + 0 + 343 = 407 ✔

3.2 怎样拆出每一位

三种拆法（设 n 是那个数）： 百位：n / 100
十位：n / 10 % 10
个位：n % 10
通用规律　想要第 k 位（从右往左，从 0 开始数）：n / 10k % 10
用 407 演算一遍，看为什么这样拆 TEXT 
n = 407

个位：407 % 10 = 7                    ← 直接取余
十位：407 / 10 = 40，40 % 10 = 0      ← 先丢掉个位，再取余
百位：407 / 100 = 4                   ← 直接整除 100

合起来：4³ + 0³ + 7³ = 64 + 0 + 343 = 407     ✔
记住这个套路　"/ 10k" 是把右边的 k 位砍掉，"% 10" 是只留最低位

4　模拟法

Simulation

4.1 按规则一步步推演

有些题不是"找答案"，而是"照着规则走一遍，看最后变成什么样"。
这种就叫模拟法——题目怎么说，你就怎么写。

例题：报数游戏 C++ 
规则：n 个人围成一圈，从 1 号开始依次报数；
      报到 3 的人退出，下一个人重新从 1 开始报。
      问最后剩下的是几号？

模拟思路：用数组给每个人做个"在不在"的标记，
          然后一圈一圈地走，数到 3 就把标记改掉。
关键　题目怎么描述的，代码就怎么走一遍——不需要你去找公式

4.2 模拟的三个要点

写模拟题的三个要点： ① 状态要记全。题目里说的每一种情况，都要有对应的变量或数组记着。
② 顺序不能乱。规则里先说哪一步、后做哪一步，代码就得按那个顺序写。
③ "转圈"要用取余。走到末尾回到开头，标准写法是 i = (i + 1) % n。
模拟题的代码往往很长，但逻辑其实最直白——因为题目已经把步骤告诉你了。
取余为什么能"转圈"？ 因为 % n 的结果永远落在 0 ~ n−1 之间。
当 i = n−1 时，i + 1 = n，而 n % n = 0——正好回到开头。
这就是"围成一圈"在程序里最经典的写法。

5　让枚举更快

Optimizing Enumeration

5.1 缩小范围

同样正确，但快得多 C++ 
【题目】求 1 到 1000 之间所有的水仙花数

【笨办法】从 1 试到 1000
for (int i = 1; i <= 1000; i++)
    检查 i 是不是水仙花数
→ 试 1000 次

【好办法】水仙花数一定是三位数
for (int i = 100; i <= 999; i++)
    检查 i 是不是水仙花数
→ 只试 900 次，结果完全一样
结论　合理的缩小范围不会漏解，只会更快——这正是"好算法"的体现
怎么知道该缩小到哪？ 问自己一句："答案有没有可能出现在这个范围之外？"
水仙花数必须是三位数 → 100 以下和 1000 以上都不可能 → 那就没必要试。
兔子数不能超过头数 → 循环到"头数"就够了。
范围缩得越小，程序跑得越快。

5.2 提前退出与剪枝

找到就停 / 不可能就跳过 C++ 
// 【技巧一】只要一个答案 → 找到就 break
for (int i = 1; i <= 1000; i++) {
    if (满足条件(i)) {
        cout << i;
        break;              // ★ 立刻退出，后面的不用试了
    }
}

// 【技巧二】提前判断"不可能"→ 直接跳过这一轮
for (int t = 0; t <= tou; t++) {
    if (t * 4 > jiao) continue;   // 脚的数超了，后面的更不可能
    int j = tou - t;
    if (t * 4 + j * 2 == jiao) { 输出答案; break; }
}
两个技巧　break 是"够了就停"；continue 是"这条不用看了"
枚举题的三步走： ① 想清楚枚举什么（枚举哪个量、范围是多少）；
② 写"条件判断"（什么样的方案算合格）；
③ 再考虑优化（能不能缩小范围、能不能提前退出）。
先写对，再写快——这个顺序千万别颠倒。

关卡

扫雷

进入关卡 →
故事：矿井通道的地面上铺着一整片石板，有些底下埋着雷。
哈利把锤子往地上一顿：这一关没法投机取巧——你得把每一格都看一遍。
你点点头：那就一格一格地查。查过的做个记号，别回头再查一遍。
他笑了：你说的正是枚举的两条铁律：不重、不漏。

思路：用两层循环把整片区域逐格检查一遍， 每检查一格就按规则处理，查过的绝不回头。

两层循环，不重不漏 C++ 
#include <iostream>
using namespace std;

int main() {
    int R = 6, C = 6;               // 6 行 6 列

    int total = 0;                  // 统计总共查了多少格

    for (int r = 0; r < R; r++) {           // 外层管行
        for (int c = 0; c < C; c++) {       // 内层管列
            total++;                        // 每查一格就记一次

            // 按照规则判断这一格该怎么处理
            if ((r + c) % 2 == 0) {
                // 偶数格：安全
            } else {
                // 奇数格：需要处理
            }
        }
    }

    cout << total << endl;                    // 36
    return 0;
}
OUTPUT　36
验算　6 行 × 6 列 = 36 格——这就是"不重不漏"的样子：每一格都被查了一次，且只查一次
和本单元的关系： 两层循环穷举所有格子，是枚举法最直观的一种形式。
判断"不重不漏"有个简单办法：把循环的次数数出来， 看它是不是正好等于"所有情况的个数"。
上例里 6×6 = 36，和输出一致——说明确实没重也没漏。

7　常见陷阱

Common Pitfalls
扣哒鸭 · 调试官
枚举题的错法高度统一——四条，记住就不丢分。
1
循环端点写错，漏掉了边界那一项。
扣哒鸭：枚举所有的三位数，得写 i <= 999。
写成 i < 999 就正好漏掉 999 这一个数——
而答案很可能偏偏就藏在被你漏掉的那个数里。
检查方法：把边界值代进去，看看第一个和最后一个有没有被算到
2
拆各位数字时把 / 和 % 用反了。
扣哒鸭：/ 是"砍掉右边的位"，% 是"只留最低位"。
个位用 n % 10，百位用 n / 100——千万别反过来写。
拿 407 心算一遍就知道了。
记牢：第 k 位 = n / 10k % 10
3
该 break 的地方没 break，多输出了答案。
扣哒鸭：题目说"输出第一个满足条件的数"，你就得在输出后 break。
不然循环会继续跑，把后面所有符合条件的数都打出来—— 判题系统看到多余输出，直接判错。
记住：只要一个答案就 break
4
为了"优化"把枚举范围缩得过头，漏掉了正确答案。
扣哒鸭：缩小范围的前提是"答案确实不可能落在外面"。
比如把三位数的范围缩成 100~500，那 407 就被你排除掉了——
而 407 恰恰是正确答案之一。
原则：先保证不漏，再考虑快；不确定就别缩

改编自 2026 年 6 月 · C++ 三级 · 判断题 第 9 题判断题
枚举可以在保证不漏解的前提下缩小枚举范围，不是必须遍历全部可能。（　　）
查看答案与详解
答案：正确（√）。枚举的核心要求是"不重不漏"， 而不是"必须把所有可能的数都试一遍"。
举例：
① 求三位数的水仙花数，枚举 100 ~ 999 就够了—— 因为小于 100 和大于 999 的数在定义上就不可能是水仙花数。
② 鸡兔同笼里，兔的只数不可能超过头的总数，循环到 tou 就可以停。
关键判断标准："答案有没有可能落在这个范围之外？" 只要不可能，缩掉就没有风险。
反过来要小心：盲目缩小范围（比如把 100~999 缩成 100~500）会把 407 这类正确答案一起排除掉。
对应小节5.1 缩小范围。
改编自 2026 年 9 月 · C++ 三级 · 第 3 题单选题
下面程序的运行结果是（　　）。
int x = 1;
for (int i = 0; i = 0; i <= 5) {
    x++;
}
cout << x << endl;
A.1　　B.10　　C.15　　D.程序编译错误
查看答案与详解
答案：A。for 的三段分别是"起点、条件、推进"。
这里的第二段写的是 i = 0——这是赋值，不是比较。
执行时：先做起点（i 变 0），再检查条件 i = 0—— 这个表达式的值是 0（假），所以循环体一次都不执行。
x 从头到尾都是 1，输出 1。
为什么不报编译错误？因为 i = 0 是个合法的表达式，编译器最多给个警告。
枚举题里这类错误特别致命：循环一次都没跑，看起来"程序正常结束"， 实际上是一个答案都没试过。
对应小节2.2 起点、终点与步长。
原创练习题单选题
下面这个程序的作用是（　　）。
int cnt = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0 && i % 5 == 0) cnt++;
}
cout << cnt;
A.统计 1 到 100 中能被 3 或 5 整除的数的个数
B.统计 1 到 100 中能同时被 3 和 5 整除的数的个数
C.统计 1 到 100 中既不能被 3 也不能被 5 整除的数的个数
D.求 1 到 100 中所有能被 3 整除的数的和
查看答案与详解
答案：B。关键在于 && 是"并且"—— 两个条件都要满足才会计数。
i % 3 == 0 表示能被 3 整除， i % 5 == 0 表示能被 5 整除，合起来就是"能同时被 3 和 5 整除"。
结果：1~100 里能同时被 3 和 5 整除的数就是 15 的倍数， 15、30、45、60、75、90，共 6 个。
A 项的写法应该用 ||（逻辑或）； C 项应该写 i % 3 != 0 && i % 5 != 0。
对应小节2.1 不重不漏。
原创练习题单选题
一个三位数 n，要取出它的十位数字，正确的写法是（　　）。
A.n / 10　　B.n % 10　　C.n / 10 % 10　　D.n % 10 / 10
查看答案与详解
答案：C。取某一位的口诀："先砍掉右边的，再只留最低位"。
① n / 10——把个位砍掉，此时最低位变成原来的十位；
② 再 % 10——只保留最低位，就得到了十位数字。
用 407 验算：407 / 10 = 40，40 % 10 = 0—— 十位是 0 ✔
A 项得到的是 40，不是一位数字；B 项是个位；
D 项先 % 10 得 7，再 / 10 得 0—— 虽然本题碰巧也是 0，但意思完全错了（换个数的结果就不一样）。
通用写法：第 k 位 = n / 10k % 10。
对应小节3.2 怎样拆出每一位。
原创练习题判断题
要统计 1 到 100 中所有偶数的个数， 写成 for (int i = 2; i <= 100; i += 2) 和 写成 for (int i = 1; i <= 100; i++) 再加 if (i % 2 == 0) 判断， 两种写法的结果相同。（　　）
查看答案与详解
答案：正确（√）。两种写法都能数出 50 个偶数，结果完全一致。
区别在效率：
第一种只循环 50 次——每一步都是偶数，不用判断。
第二种循环 100 次——里面有一半被 if 挡掉了，白跑 50 次。
结论："调整步长"是枚举优化最常用的手段之一—— 把不需要的情况从循环里直接排除，比"先跑一遍再判断"更快。
同类例子：求 1~100 的奇数用 i = 1; i += 2。
对应小节5.1 缩小范围。
原创练习题编程题
百钱买百鸡：公鸡 5 钱一只，母鸡 3 钱一只，小鸡 1 钱三只。 用 100 钱买 100 只鸡，问公鸡、母鸡、小鸡各多少只？（输出所有方案，每行三个数）
查看参考答案与要点 
#include <iostream>
using namespace std;

int main() {
    // g：公鸡  m：母鸡  x：小鸡
    for (int g = 0; g <= 20; g++) {            // 5g ≤ 100 → g ≤ 20
        for (int m = 0; m <= 33; m++) {        // 3m ≤ 100 → m ≤ 33
            int x = 100 - g - m;               // 小鸡的只数不用枚举！
            if (x < 0 || x % 3 != 0) continue; // 小鸡必须是 3 的倍数

            if (5 * g + 3 * m + x / 3 == 100) {
                cout << g << " " << m << " " << x << endl;
            }
        }
    }
    return 0;
}

输出：
0 25 75
4 18 78
8 11 81
12 4 84
要点：
① 最关键的一步是"只枚举两个量"——因为总数固定是 100， 所以 x = 100 − g − m，小鸡的数量直接算出来就行。 这比三层循环快了整整一百倍；
② 范围要缩到最小：公鸡最多买 100÷5 = 20 只，母鸡最多 100÷3 = 33 只，
没必要从 0 试到 100；
③ x % 3 != 0 的判断不能少——小鸡是"1 钱三只"，只数必须是 3 的倍数；
④ 用 continue 提前跳过不可能的情况，代码更干净；
⑤ 价格算的是 x / 3（整除），保证不会出现小数。
对应小节5.1 缩小范围；5.2 提前退出与剪枝。

原创练习题编程题
数字反转：读入一个正整数 n，输出把它各位数字倒过来之后得到的新数。 （例如 12345 → 54321；1200 → 21）
查看参考答案与要点 
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    int rev = 0;
    while (n > 0) {
        rev = rev * 10 + n % 10;    // 取最低位，接到 rev 的右边
        n /= 10;                     // 砍掉最低位
    }

    cout << rev << endl;
    return 0;
}

输入 12345 输出：54321；输入 1200 输出：21
要点：
① n % 10 取最低位、n /= 10 砍掉最低位—— 这一对操作是"逐位处理数字"的万能钥匙，和水仙花数拆位是同一个道理；
② rev = rev * 10 + 新位 的意思是 "把已有的结果整体左移一位，再把新数字放到个位"——就像往一个数右边不断接数字；
③ 用 while (n > 0) 而不是 for， 因为事先不知道 n 有几位；
④ 1200 反转后是 21 而不是 0021—— 因为前导零在整数里本来就存不住，这正是我们要的效果。
对应小节3.2 怎样拆出每一位。

Unit Summary
哈利 · 铁匠
四句话记住枚举与模拟：
一、枚举就是"把所有可能挨个试过去"——笨，但只要范围对了就一定不会漏。
二、铁律是"不重不漏"；动手前先定好起点、终点、步长这三件事。
三、模拟就是"题目怎么说，你就怎么写"——状态记全、顺序别乱、转圈用取余。
四、优化要放在写对之后：能缩范围就缩，只要一个答案就 break。
矿坑走到头了。下一站我们出矿洞——齿轮高台在等着，那里有传送带、货架和装配台。

你在矿灯墙前收获了什么

  • 枚举法——把所有可能逐个检验，筛出符合条件的；骨架就是"循环 + 判断"。
  • 不重不漏——枚举的铁律，也是绝大多数错误的总源头。
  • 三要素——起点、终点、步长；端点写 < 还是 <= 最容易错。
  • 拆各位数字——第 k 位 = n / 10k % 10；个位 n % 10、百位 n / 100。
  • 水仙花数——三位数，各位立方和等于自身；答案是 153、370、371、407。
  • 数字反转——rev = rev * 10 + n % 10; 配合 n /= 10。
  • 模拟法——照规则一步步推演；状态记全、顺序别乱、转圈用取余。
  • 转圈的写法——i = (i + 1) % n，走到末尾自动回到开头。
  • 缩小范围——只要"答案不可能落在外面"，缩掉就更快且不影响正确性。
  • 提前退出——只要一个答案就 break；不可能的情况用 continue 跳过。
  • 优化顺序——先写对，再写快。
